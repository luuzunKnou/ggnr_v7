# 작업계획서

2026-07-03 | 213am | 레이어 업로드

## 개발목표

SHP 파일 업로드·동기화 후 이력 조회 목록의 «업데이트 내용» 열에 표시되는 문구가 실제 처리 결과와 맞지 않는 문제를 해결한다. 동기화 처리 후 «동기화 완료 ()»처럼 괄호만 비어 보이는 경우와, 일반 업로드가 구분 없이 «업데이트 완료»만 표시되는 경우를 모두 정리한다.

동기화 완료 문구는 화면에서 임의로 계산하지 않고, 서버에서 해당 이력과 연결된 동기화 기록만 기준으로 집계해 저장한다. 일반 업로드는 신규·업데이트·변경 없음에 따라 괄호 안에 건수나 변경 요약을 붙인다. 이미 저장된 과거 이력도 동일 규칙으로 일괄 재계산해 교정한다.

## 플로우차트

```
SHP 업로드 → (동기화 필요) → 동기화 상세 → 반영·유지·롤백 → 서버 집계 → 이력 «업데이트 내용» 갱신
SHP 업로드 → (동기화 불필요) → 업로드 완료 → 유형별 문구 저장 → 이력 «업데이트 내용» 표시
과거 이력 → 일괄 재계산 스크립트 → «업데이트 내용» 교정
```

## 화면설계

### DEV-SHP-HIST-01 SHP 이력 조회 목록

```
+----------------------------------------------------------------------+
| SHP 파일 업로더                                                      |
| [업로드]  [이력 조회]                                                |
+------+--------------+--------+----------------------------+----------+
| 결과 | 레이어       | 구분   | 업데이트 내용              | 액션     |
+------+--------------+--------+----------------------------+----------+
| 성공 | 기본계획     | 동기화 | 동기화 완료 (유지 3)       | 동기화   |
| 성공 | 도로대장     | 신규   | 업데이트 완료 (신규 1200건)| -        |
| 대기 | 하천망       | 동기화 | 동기화 대기                | 동기화   |
+------+--------------+--------+----------------------------+----------+
```

#### 설명

1. «이력 조회» 탭에서 업로드 배치별 상세 행을 펼치면 «업데이트 내용» 열에 처리 결과 요약이 표시된다.
2. 동기화를 거친 레이어는 «동기화 완료» 뒤에 신규·충돌·삭제·유지 건수가 괄호 안에 붙는다.
3. 동기화 없이 끝난 레이어는 «업데이트 완료» 뒤에 신규 건수, 이전→현재 건수, 또는 «변경 없음»이 붙는다.
4. 처리 결과가 하나도 없으면 «동기화 완료»만 표시하고 빈 괄호는 쓰지 않는다.
5. «동기화 대기»·«실패» 등 기존 상태 문구는 그대로 유지한다.

#### 확인사항

1. 동기화 후 유지만 한 경우 «동기화 완료 (유지 N)» 형태로 표시되어야 한다.
2. «동기화 완료 ()»처럼 괄호만 비어 있는 문구가 새로 저장되지 않아야 한다.
3. 신규 업로드는 «업데이트 완료 (신규 N건)» 형태로 구분되어야 한다.
4. 기존 데이터와 동일한 업로드는 «업데이트 완료 (변경 없음)»으로 표시되어야 한다.
5. 과거에 «업데이트 완료»만 적혀 있던 행도 재계산 후 상세 문구로 바뀌어야 한다.

### DEV-SHP-SYNC-01 동기화 상세 모달

```
+----------------------------------------------------------------------+
| 동기화 상세 - RIVER_PLAN_AS                                   [닫기] |
+----------------------------------------------------------------------+
| [전체] [미결] [충돌] [유지] [신규] [삭제]                            |
+--------+----------+----------+----------+----------------------------+
| 키값   | 필드     | DB 값    | SHP 값   | 처리                       |
+--------+----------+----------+----------+----------------------------+
| 001    | n_name   | 동산천   | 동산천2  | [반영] [유지]              |
| 002    | remark   | (없음)   | 비고2    | [반영] [유지]              |
+--------+----------+----------+----------+----------------------------+
| [전체 반영] [전체 유지] [전체 건너뛰기]                              |
+----------------------------------------------------------------------+
```

#### 설명

1. 이력 목록에서 «동기화»를 누르거나 대기 행을 클릭하면 동기화 상세 모달이 열린다.
2. 사용자가 «반영»·«유지»·«롤백» 등 처리를 마치면 목록을 다시 불러온 뒤 서버에 완료 집계를 요청한다.
3. 미결 건이 하나라도 남아 있으면 이력 «업데이트 내용»은 «동기화 대기» 상태를 유지한다.
4. 모든 건이 처리되면 서버가 연결된 동기화 기록만 집계해 «동기화 완료 …» 문구를 저장한다.
5. 화면은 처리 후 이력 조회 목록을 새로고침해 갱신된 «업데이트 내용»을 보여 준다.

#### 확인사항

1. 전체 유지 후 이력 목록에 «동기화 완료 (유지 N)»이 반영되어야 한다.
2. 전체 반영 후 신규·충돌·삭제 건수가 괄호 안에 맞게 표시되어야 한다.
3. 롤백만 있고 반영·유지 건이 없으면 «동기화 완료»만 표시되어야 한다.
4. 처리 도중 모달을 닫아도 미결 상태에서는 «동기화 대기»가 유지되어야 한다.
5. 동기화 상세를 다시 열었을 때 처리 결과와 목록 문구가 일치해야 한다.

### DEV-SHP-UP-01 SHP 업로드 완료

```
+----------------------------------------------------------------------+
| SHP 파일 업로더                                                      |
+----------------------------------------------------------------------+
| [업로드]  [이력 조회]                                                |
+----------------------------------------------------------------------+
| 하천망.shp   테이블 O  레이어 O  스타일 O  정의 O                    |
+----------------------------------------------------------------------+
| 후처리 진행 중...                                                    |
+----------------------------------------------------------------------+
```

#### 설명

1. SHP 파일을 선택해 후처리가 끝나면 배치 단위로 이력이 저장된다.
2. 동기화가 필요 없는 파일은 구분(신규·업데이트·동일)과 이전·현재 건수로 «업데이트 완료 …» 문구를 만든다.
3. 동기화가 필요한 파일은 «동기화 대기»로 저장하고, 이후 동기화 상세에서 처리하면 «동기화 완료 …»로 바뀐다.
4. 마법사 형태의 DB 반영 화면도 동일한 문구 규칙을 따른다.
5. 저장된 문구는 이력 조회 목록의 «업데이트 내용» 열에 그대로 노출된다.

#### 확인사항

1. 최초 업로드(신규) 직후 이력에 «업데이트 완료 (신규 N건)»이 저장되어야 한다.
2. 기존 테이블 덮어쓰기(업데이트)는 «업데이트 완료 (이전 → 현재건)» 형태여야 한다.
3. 변경 없이 통과한 파일은 «업데이트 완료 (변경 없음)»이어야 한다.
4. 동기화 필요 파일은 «동기화 대기»로만 저장되고 «업데이트 완료»와 혼동되지 않아야 한다.
5. 업로드 탭과 마법사 화면에서 같은 규칙의 문구가 저장되어야 한다.
