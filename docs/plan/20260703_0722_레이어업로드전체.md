## 개발목표

dev `SHP 파일 업로더`·파일 변환기 SHP 탭에서 폴더 업로드부터 DB·GeoServer·레이어·필드 정의·동기화·이력·SHP 다운로드까지 한 흐름으로 점검·재시도할 수 있게 한다. `레이어·필드 정의`는 지도 앱에서 레이어 목록·속성 표시에 쓰는 설정(테이블·필드 메타)을 등록·보강하는 단계이다. 엑셀 마법사와 단계·용어를 맞추고, 컬럼 불일치 시 업로드를 막으며, 시스템 입력 DB row는 SHP 재업로드 시 유지·변경을 사용자가 선택한다.

## 플로우차트

```
폴더 업로드 → 좌표계 확인 → 컬럼 검증(불일치 시 중단) → 테이블(DB·동기화) → GeoServer → 스타일 → 레이어·필드 정의 → 이력 저장 → (동기화 필요) 동기화 상세 → 완료 집계 / (실패) 해당 단계부터 재실행 / 레이어 상태 → 누락 재실행·SHP 다운로드
```

## 화면설계

- 와이어프레임은 **전체화면**을 기준으로 한다.
- 아래 화면은 실제 사용 순서대로 기술한다.
  - [ SHP 업로드 ] 탭에서 폴더업로드·후처리 → (필요 시) 좌표계 확인 모달 → [ 이력 조회 ] 탭에서 결과 확인·동기화 → [ 레이어 상태 ] 탭에서 누락·복구



### DEV-SHP-MASTER-01 SHP 파일 업로드

```
+----------------------------------------------------------------------------------------------------------------------+
|개발자 모드                                                                         [테마변경]  [로그아웃]  [메인으로]|
+------------------------+---------------------------------------------------------------------------------------------+
|> 시스템관리            |SHP File Uploader                                                                            |
|> 데이터관리            |SHP 파일 업로드 및 GeoServer·스타일 확인·후처리                                            |
|> Tools                 |[x] SHP 업로드   |   [ ] 레이어 상태   |   [ ] 이력 조회                                     |
|v 기타기능              |---------------------------------------------------------------------------------------------|
|  * SHP File Uploader   |[상위로]  shp_data/20250703                                         [새로고침]  [폴더 업로드]|
|    Excel File Uploader |---------------------------------------------------------------------------------------------|
|    Data File Upload    |업로드 진행: 12 / 12 파일                                                              [취소]|
|    정사영상관리        |후처리 진행: 2 / 5                                                                           |
|    LAS File Uploader   |+--------------+--------+-------+-------+--------+------+------+------+---------------------+|
|    LAS Fixer           |  파일         |  Table | Layer | Style | Define | 현재 | 변경 | 추가 | 비고                 |
|> 버전관리              |  하천망.shp   | 동기화 | 기존  | 기존  |  기존  |   0  |  33  |   0  | 충돌33/삭제/0/신규0  |
|                        |  도로대장.shp |  기존  | 기존  | 기존  |  기존  |   0  |   -  |   -  |                      |
|                        |+--------------+--------+-------+-------+--------+------+------+------+---------------------+|
+------------------------+---------------------------------------------------------------------------------------------+
+----------------------------------------------------------------------------------------------------------------------+
```



#### 설명

1. 폴더명은 `YYYYMMDD_좌표계 4자리 숫자_레이어 그룹_업데이트 내용` 의 규칙을 따른다. 규칙이 지켜지지 않아도 업로드는 가능하다.
2. GIS 담당자가 SHP 폴더를 올리면 **개발자 모드** 우측 화면에서 파일마다 `지도에 쓰이기까지` 어느 단계까지 진행됐는지 한눈에 본다.
3. 상단 `[ SHP 업로드 ]`·`[ 레이어 상태 ]`·`[ 이력 조회 ]`로 각각 `파일 올리기`·`점검·복구`·`과거 작업내역 보기`를 나눈다.
4. 전송이 끝나면 파일별로 **Table → Layer → Style → Define** 순으로 자동 후처리가 이어진다. 좌표계 확인은 `정사영상관리` 의 좌표계 자동탐지 기능을 이식 후 Table 생성 앞에 추가된다.
5. 좌표계 선택·동기화·컬럼 불일치처럼 담당자가 직접 처리해야 할 일이 생기면 그 파일만 대기·실패로 남고, 나머지 파일은 계속 처리된다.
6. Table·Layer·Style·Define 열은 `생성`·`기존`·`동기화`·빨간 `X`(실패)·`-`(미실행)으로 표시된다. 비고에는 서버 오류 문장이 그대로 나오거나, 동기화 대기 시 `충돌 N / 삭제 N / 신규 N` 링크가 나온다. Table 실패 시 후속 열은 실행되지 않아 `-`로 남는다.



#### 확인사항

1. 한 폴더에 파일이 여러 개일 때 각 파일 행이 서로 섞이지 않고 구분되어야 한다.
2. `동기화 대기` 파일은 동기화 상세에서 처리하기 전까지 `완료`로 표시되지 않아야 한다.
3. 배치가 끝난 뒤 [ 이력 조회 ] 탭에 이번 작업 기록이 남아야 한다.
4. 파일 변환기 SHP 마법사와 단계 이름·순서·결과 표현이 같아야 한다.
5. 한 파일이 컬럼 불일치로 중단되어도 같은 경로의 다른 파일 후처리는 계속되어야 한다.

#### 설명

1. SHP만으로 좌표계를 확실히 알 수 없을 때, `이 파일이 어느 좌표계로 그려졌는지` 담당자가 고르는 모달이다. 모달이 뜨면 **뒤 화면은 어둡게** 처리된다.
2. 후보 카드는 **위쪽**에 좌표계 이름·일치율·읍면동 교차 여부, **아래쪽**에 **항공영상 배경 지도 미리보기**를 둔 2열 구성이다. 지도 영역 안에 SHP 범위(네모)가 그려져 후보마다 위치 차이를 눈으로 비교한다.
3. 카드를 고른 뒤 `좌표계 저장`을 누르면 그 좌표계로 DB에 넣을 준비가 되고, 해당 파일 후처리가 이어진다.
4. `취소`를 누르면 이 파일만 중단되고, 폴더에 남은 다른 파일 처리는 계속된다.
5. 정사영상관리 `원본 좌표계 선택`과 같은 배치·조작감을 유지한다.



#### 확인사항

1. prj·파일명·폴더명 규칙만으로 판별 가능할 때는 이 화면이 뜨지 않아야 한다.
2. 후보가 여러 개일 때 일치율과 **지도 미리보기(항공영상 + SHP 범위)** 가 함께 보여야 하며, 일치율이 같아도 지도에서 범위 위치가 다르면 사용자가 구분할 수 있어야 한다.
3. 저장 후 DB·지도 반영 좌표는 **EPSG:5181**로 변환되어야 한다.



### DEV-SHP-SCHEMA-01 컬럼 불일치 모달

```
+-----------------------------------------------------------------------------------------------------------------+
|개발자 모드                                                                    [테마변경]  [로그아웃]  [메인으로]|
+------------------------+----------------------------------------------------------------------------------------+
|> 시스템관리            |SHP File Uploader                                                                       |
|> 데이터관리            |SHP 파일 업로드 및 GeoServer·스타일 확인·후처리                                       |
|> Tools                 |[x] SHP 업로드 | [ ] 레이어 상태 | [ ] 이력 조회                                        |
|v 기타기능              |----------------------------------------------------------------------------------------|
|  * SHP File Uploader   |(뒤 화면 어둡게 · 후처리 중)                                                           |
|    Excel File Uploader |            +----------------------------------------------------------+                |
|    Data File Upload    |              컬럼 검증 실패 - river_d_index.shp                [닫기]                  |
|    정사영상관리        |              SHP와 DB 테이블의 컬럼 구성이 다릅니다.                                   |
|    LAS File Uploader   |              SHP에만 있음: new_col                                                     |
|    LAS Fixer           |              DB에만 있음: old_col                                                      |
|> 버전관리              |              타입 불일치:  (SHP: integer / DB: numeric)                                |
|                        |                                                                              [ 확인 ]  |
|                        |            +----------------------------------------------------------+                |
+------------------------+----------------------------------------------------------------------------------------+
```



#### 설명

1. 이미 DB에 같은 이름의 레이어 테이블이 있을 때, 같은 이름의 SHP를 다시 올리는 경우에만 검사한다.
2. 처음 만드는 레이어는 검사하지 않고 바로 테이블 생성으로 넘어간다.
3. 검사는 SHP 속성 컬럼 목록과 DB 테이블 컬럼 목록을 맞춰 보는 것이다.
4. SHP에만 있는 컬럼이 있으면 불일치다. (새 SHP에는 있는데 DB에는 없음)
5. DB에만 있는 컬럼이 있으면 불일치다. (DB에는 있는데 이번 SHP에는 없음)
6. 이름은 같으나 TEXT - NUMBER 등 타입이 어긋난 컬럼이 있으면 불일치다.
7. 불일치가 있으면 동기화·행 비교·테이블 덮어쓰기 전에 안내 모달이 뜬다. 후처리 화면 위에 겹쳐 보인다.
8. 이 모달 단계에서는 DB 테이블·데이터·동기화 기록을 바꾸지 않는다. 담당자는 목록을 보고 SHP 또는 DB를 맞춘 뒤 다시 업로드한다.
9. 해당 SHP 파일만 중단·실패로 남고, 같은 폴더의 다른 파일은 계속 처리된다.



#### 확인사항

1. 불일치 유형(SHP만·DB만·종류 상이)이 한 줄씩 구분되어 보여야 한다.
2. `확인`을 눌러도 DB 데이터·동기화 기록이 생기지 않아야 한다.
3. 불일치 파일만 실패로 남고 같은 배치의 다른 파일은 계속 처리되어야 한다.



### DEV-SHP-SYNC-01 동기화 상세 (충돌·삭제·신규)

```
+------------------------------------------------------------------------------------------------------------------+

|    LAS Fixer           |  | 미결 33건                                                [전체 반영]  [전체 유지] |  |
|> 버전관리              |  | +------+------+-----------+-----+----------+------------------------------------+ |  |
|                        |  | | 상태 | 구분 |    액션   | key | 변경필드 |              값                    | |  |
```

#### 설명

1. 새 SHP를 DB에 반영하기 전, **키가 같은 행끼리** DB 기존 데이터와 비교한 차이를 한곳에서 처리하는 모달이다. 모달 뒤 화면은 **어둡게** 처리된다.
2. 값이 다른 행(충돌), SHP에는 없는 DB 행(삭제 후보), DB에는 없는 SHP 행(신규)을 탭으로 나눠 본다.
3. 충돌 줄은 SHP 값을 따를지 `DB 유지`할지 줄마다 고른다.
4. 목록 «변경필드»·«값»은 **바뀐 항목마다 한 줄**씩 쓴다. 같은 key라도 변경 필드가 두 개 이상이면 **각각 별도 행**으로 나눈다. `geom`**만** 바뀌어도 `—` 대신 변경필드 `geom`을 쓴다. geom **타입은 같고 위치만** 다르면 값은 `위치변경` 만 적는다. geom **타입까지** 바뀌면 `{타입} · {사유}` 형식(예: `Point · 위치변경->Line · 위치변경`)으로 **DB 요약->SHP 요약**을 적는다. 속성은 `도로A->도로B`처럼 **기존->변경**만 적는다.
5. 삭제 후보 중 시스템에서 직접 넣은 행은 `DB 유지`로 남길 수 있고, SHP에 없으니 지워도 된다고 판단되면 `삭제 반영`을 고른다.
6. 모두 처리하면 GeoServer·스타일·필드 정의 등 남은 단계와 [ 이력 조회 ] 탭의 처리 요약이 갱신된다.
7. **현행:** [ SHP 업로드 ] 탭 동기화 링크와 [ 이력 조회 ] 탭 동기화는 같은 모달이지만, **이력 쪽은 업로드 탭과 연동되지 않아** 건수·내역이 비거나 어긋날 수 있다.



#### 확인사항

1. `DB 유지`를 고른 삭제 후보 줄은 SHP에 없어도 DB에서 사라지지 않아야 한다.
2. 충돌용·삭제용 `DB 유지` 안내 문구가 서로 달라야 한다.
3. 처리하지 않은 줄이 하나라도 남으면 업로드 화면·이력에 `동기화 대기`가 유지되어야 한다.
4. 완료 후 이력 `업데이트 내용` 괄호 안 건수가 실제 반영·유지·삭제와 일치해야 한다.
5. 비교에 쓰는 **키 컬럼**이 설정되지 않은 레이어는 동기화를 시작할 수 없고, 그 이유가 안내되어야 한다.
6. 업로드 탭·이력 탭 어느 쪽 [동기화]로 열어도 같은 건수·내역이 보여야 한다.
7. geom 타입은 같고 위치만 바뀐 줄은 변경필드 `geom`, 값 `위치변경` 으로 보여야 한다.
8. geom 타입까지 바뀐 줄은 `{타입} · {사유}` 형식(예: `Point · 위치변경->Line · 위치변경`)으로 보여야 한다.
9. 같은 key에 속성·geom이 함께 바뀌면 목록에 **변경 필드별로 두 줄 이상** 나뉘어 보여야 한다.

#### 설명

1. 동기화 내역(SYNC-01)에서 충돌·신규·삭제 줄을 클릭하면, **현재 화면** 위에 «상세 정보» 모달이 한 겹 더 뜬다. 뒤에는 동기화 내역이 **어둡게** 보인다.
2. **현행:** 속성 표에서 `geom`은 없고, DB·SHP 각각 **미니 지도**로만 위치를 본다. 위치·도형만 다른 충돌은 목록 «변경필드»가 `—`로 보일 수 있다.
3. **개선:** `geom` 행은 DB·SHP 각각 표시한다. **타입은 같고 위치만** 다르면 양쪽 모두 `위치변경` 만 적는다. **타입까지** 바뀌면 `{타입}·{사유}` 로 적는다(예: DB `Point·위치변경` | SHP `Line·위치변경`). 값이 다르면 **다른 속성과 같은 노란 배경**으로 강조한다.
4. 미니 지도는 **표 아래**에 그대로 둔다. 지도에서 위치·모양 차이를 확인한다.
5. **목록(SYNC-01)** 과 같은 geom 표기 규칙을 쓴다. 목록은 필드마다 별도 행이고, 상세 모달에서는 **한 key의 전체 비교**를 본다.



#### 확인사항

1. geom **타입까지** 바뀐 경우 DB `Point·위치변경`·SHP `Line·위치변경`처럼 **타입·사유**가 각각 보이고 노란 배경으로 강조되어야 한다.
2. geom **타입은 같고** 좌표만 다를 때 양쪽 모두 `위치변경` 만 보여야 한다.
3. 목록에서 속성과 geom이 함께 바뀌면 `name` 줄·`geom` 줄이 **각각 한 행**으로 보여야 한다.
4. `geom`이 바뀌지 않은 줄에는 `geom` 행이 없거나 강조 없이 보여야 한다.
5. 미니 지도는 DB·SHP 각각 표 아래에 계속 보여야 한다.
6. «반영»·«유지» 동작은 기존 속성 충돌과 동일해야 한다.
