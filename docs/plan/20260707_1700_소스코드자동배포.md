## 개발목표

관공서·폐쇄망 환경에서 개발 PC → 중앙 서버(GNMS) → 운영 서버로 이어지는 소스 배포 흐름을 하나의 업무 절차로 정리·구현한다.

개발자는 «소스코드 업로더»로 현재 워크스페이스를 중앙 서버에 올려 최신 소스를 만들고, «버전관리»의 «설치파일 다운로드»로 초기 세팅용 압축 파일(현재 서버 전체)을 받을 수 있다. 현장 담당자는 «최신 소스 적용»으로 중앙 서버가 보관한 최신 소스 압축 파일을 조회·다운로드한 뒤 브라우저가 중계해 운영 서버에 반영한다. 운영 서버는 중앙 서버에 직접 접속하지 않는다. 적용 후 재시작 옵션으로 운영 서버를 갱신한다.

«버전관리» 화면은 좌우 세로 분할로 왼쪽 «설치파일 다운로드», 오른쪽 «최신 소스 적용»을 한 행에 동시에 보여 준다. 설치·최신소스 적용 모두 동일한 폐쇄망/개방망 선택 버튼으로 패키지 폴더 포함 여부를 결정한다(기본값 폐쇄망). «소스코드 업로더»에도 node_modules 포함/미포함 선택용 선택 버튼을 두고 **기본값은 미포함**이다. 미포함 선택 시 압축·전송에서 node_modules를 제외하고, 원격 병합/압축 해제 직후 중앙 서버에서 npm install 단계를 진행한다. 포함 선택 시 node_modules를 압축에 넣고 npm install 단계는 생략한다. 소스코드 업로더에서 스키마 SQL과 접속 DB가 다르면 압축·전송 전 확인 대화상자로 진행 여부를 묻고, 중단 시 업로드를 멈춘다. 설치·Node 준비 절차는 Notion 설치 매뉴얼 링크만 두고 본문은 매뉴얼에 맡긴다.

세 기능의 실행 결과는 **공통 이력 테이블**에 기록한다. 
공통 이력 테이블은 기능 구분(history_type), 성공여부(stauts), 메세지(message), IP, 생성날짜(created_at)로 구성한다. 
각 메뉴 제목 옆 «이력» 버튼으로 플로팅 패널을 열어 해당 기능 이력을 확인한다. 버전관리에서는 기능 선택(전체·설치파일 다운로드·최신 소스 적용)과 날짜로 설치·적용 이력을 조회하고, 소스코드 업로더에서는 기능 선택 없이 날짜로 업로드 이력만 조회한다. 단계별 진행·로그·실패 지점 표시를 보강하고, dev에서 업로드 → 최신 조회 → 적용 → 재시작 E2E 성공을 1차 목표로 한다.

## 플로우차트

```
(개발자) 설치 ZIP 다운로드 → 운영 및 시연 서버 셋팅 → 이력 조회

(개발자)소스코드 업로더 → GNMS 연결 확인 → 스캔 → (DB 불일치 시 확인) → 압축·청크 전송 → 원격 병합/압축 해제 → (node_modules 미포함 시 npm install) → GNMS 최신 소스 등록 →
(사용자) 최신 소스 적용 → GNMS로 최신소스 요청 → ZIP파일 형태로 전송(사용자 PC 저장 X) → 바로 운영 서버로 전송 → (옵션에 따라) 재시작 → 이력 조회
```

## 화면설계

### DEV-DEP-01 소스코드 업로더 · 업로드 준비

```
+----------------------------------------------------------------------------------------------------------------------+
|개발자 모드 [테마변경] [로그아웃] [메인으로]                                                                          |
|v 버전관리              |소스코드 업로더                                              [이력]                          |
| * 소스코드 업로더      |현재 워크스페이스 소스코드를 압축/청크 전송 방식으로 원격 서버에 업로드                      |
|  버전관리              |                                                                                             |
|> 기타기능              |( ) 설치  ( ) 업데이트 (준비 중)                                                             |
|  SHP File Uploader     |( ) node_modules 포함  (●) node_modules 미포함                                               |
|                        |[2026-07-08] [변경 사항 메모 (선택)________________]                                         |
|                        |설치: core/runtime/data 업로드. 미포함 시 원격 npm install 실행.                             |
|                        |[현재 코드 자동 업로드] [취소]                                                               |
|                        |대기 · 대상 서버 상태 확인                                                                   |
|                        |대기 · 소스 스캔/필터링                                                                      |
|                        |대기 · ZIP 압축                                                                              |
|                        |대기 · 원격 업로드 세션 생성                                                                 |
|                        |대기 · 청크 전송                                                                             |
|                        |대기 · 원격 병합/압축 해제                                                                   |
|                        |대기 · npm install                                                                           |
|                        |대기 · 결과 집계                                                                             |
+------------------------+---------------------------------------------------------------------------------------------+
```

#### 설명

1. 전송은 청크 전송 단일 경로다. 로컬 압축 후 중앙 서버로 청크 전송·병합한다.
2. 업로드 모드는 «설치»가 기본이다. «업데이트 (준비 중)»는 비활성으로 표시한다.
3. [변경] node_modules **포함/미포함** 선택 버튼을 둔다. **기본 선택은 미포함**이다. 미포함이면 스캔·압축에서 node_modules를 제외하고, 원격 병합/압축 해제 후 npm install 단계를 실행한다. 포함이면 node_modules를 압축에 넣고 npm install 단계는 «대기» 또는 «생략»으로 건너뛴다.
4. 날짜·변경 메모는 압축 메타·등록 정보에 함께 기록한다.
5. 하단 단계 목록·진행률·실시간 로그·파일 집계 영역은 업로드 시작 전에는 «대기» 상태로 보인다.
6. 우측 상단 «이력» 버튼을 제목과 같은 높이·반대편에 둔다. 클릭 시 DEV-DEP-11 플로팅 패널을 연다.

#### 확인사항

1. 청크 전송으로 업로드가 동작해야 한다.
2. node_modules 선택 버튼의 **기본값이 미포함**이어야 한다.
3. 포함·미포함 선택에 따라 스캔 제외 목록과 단계 목록(npm install 여부)이 달라져야 한다.
4. 날짜·변경 메모 입력 후 «현재 코드 자동 업로드»가 동작해야 한다.
5. 업로드 전에는 «취소»가 비활성, 진행 중에만 «취소»가 활성화되어야 한다.
6. «이력» 버튼이 소스코드 업로더 화면에 보여야 한다.

3. 실패 메시지가 실시간 로그에도 남아야 한다.

### DEV-DEP-03 소스코드 업로더 · 스캔·필터링

```
+----------------------------------------------------------------------------------------------------------------------+
|개발자 모드 [테마변경] [로그아웃] [메인으로]                                                                          |
|v 버전관리              |소스코드 업로더                                                                              |
| * 소스코드 업로더      |[현재 코드 자동 업로드] (진행 중…) [취소]                                                    |
|  버전관리              |소스 스캔/필터링 중…  12%  █████░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░                       |
|> 기타기능              |완료 · 대상 서버 상태 확인     …                                                             |
|  SHP File Uploader     |진행 · 소스 스캔/필터링     포함 1,234 · 제외 567 · 현재 경로 …                               |
|                        |                          · DB(SQL) 12 · DB(확인 필요) 3                                    |
|                        |                          · 이미지 45 · 패키지 1 · 스키마 SQL ↔ DB 차이 2건                  |
|                        |대기 · ZIP 압축 · 원격 업로드 세션 생성 · 청크 전송 · 병합 · npm install · 결과 집계         |
|                        |실시간 로그                                                                                  |
|                        |[14:30:05] 스캔 포함 1234 / 제외 567 (node_modules 제외)                                     |
+------------------------+---------------------------------------------------------------------------------------------+
```

#### 설명

1. 워크스페이스 전체를 순회하며 포함·제외·카테고리(코어/런타임/데이터)를 집계한다. node_modules **미포함** 선택 시 node_modules 경로는 제외 집계에 반영한다.
2. DB(SQL) 파일·이미지·패키지 목록·스키마 SQL과 접속 DB 비교 결과를 스캔 상세에 구분 표시한다.
3. SQL 외 DB 조작 가능 경로는 «확인 필요» 건수로 표시한다. (임의로 수정된 DB가 있을 가능성을 방지하기 위해)
4. 스키마 SQL과 접속 DB 차이가 1건 이상이면 스캔 직후 압축·전송으로 넘어가기 전에 DEV-DEP-03B 확인 대화상자를 띄운다. 차이 0건이면 대화상자 없이 다음 단계로 진행한다.

#### 확인사항

1. 포함·제외 건수와 현재 스캔 경로가 주기적으로 갱신되어야 한다.
2. DB·이미지·패키지·DB 비교 구분이 상세에 보여야 한다.
3. 접속 DB와 SQL 불일치 시 스캔 상세에 차이 건수가 보여야 한다.
4. 불일치 시 확인 대화상자 없이 자동으로 압축·전송 단계로 넘어가면 안 된다.

#### 설명

1. DEV-DEP-03과 동일한 소스코드 업로더 화면 위에 확인용 대화상자가 겹쳐 뜬다.
2. 스캔·DB 비교가 끝난 뒤, 차이 건수가 1건 이상이면 업로드 파이프라인을 일시 정지하고 대화상자를 표시한다.
3. 대화상자 본문에 차이 건수와 요약(테이블·컬럼 등 핵심만)을 적는다. 상세 목록은 로그·스캔 상세에도 남긴다.
4. «중단» 선택 시 업로드를 취소하고 «업로드 중단 — DB 스키마 불일치» 등 안내를 로그·상태에 남긴다. 압축·전송 단계로 진행하지 않는다.
5. «계속 진행» 선택 시 대화상자를 닫고 DEV-DEP-04부터 이어서 진행한다.
6. 차이 0건이면 이 대화상자는 뜨지 않는다.

#### 확인사항

1. DB 불일치 시 확인 대화상자가 반드시 떠야 한다.
2. «중단» 시 압축·전송·중앙 등록이 시작되지 않아야 한다.
3. «계속 진행» 시에만 압축·전송 단계로 넘어가야 한다.
4. 차이 0건이면 대화상자 없이 바로 다음 단계로 진행해야 한다.
5. 대화상자는 모달 형태로, 선택 전에는 뒤쪽 업로드 조작이 막혀야 한다.

#### 설명

1. 로컬 압축 → 업로드 세션 생성 → 청크 전송 → 병합·압축 해제 순으로 진행한다.
2. 이 단계는 스캔·DB 비교 완료 후, 차이 없음 또는 사용자가 «계속 진행»을 선택한 경우에만 시작한다.
3. 전체 진행률 막대와 청크 전용 보조 막대를 함께 표시한다.
4. 하단에 코어/런타임/데이터·성공/실패/스킵 집계를 표시한다. 완료 후 파일별 상태 목록(스크롤)을 확장 표시한다.

#### 확인사항

1. 압축·세션 생성·청크·병합 단계가 순서대로 표시되어야 한다.
2. DB 불일치 후 «중단»을 누른 경우 이 단계에 도달하지 않아야 한다.
3. 청크 진행률이 막대·로그에 반영되어야 한다.
4. 중간 «취소» 시 진행이 중단되어야 한다.

#### 설명

1. [신규] 원격 병합/압축 해제 **직후** 실행되는 단계다. node_modules **미포함** 선택 시에만 진행한다.
2. 중앙 서버(업로드 대상) 워크스페이스 루트에서 npm install을 실행하고, 진행 메시지·로그를 실시간 표시한다.
3. node_modules **포함** 선택 시 이 단계는 «생략» 또는 즉시 «완료» 처리하고 결과 집계로 넘어간다.
4. npm install 실패 시 해당 단계가 «실패»로 표시되고 오류 요약이 로그·상세에 남는다. 결과 집계는 실패 상태로 마무리한다.

#### 확인사항

1. node_modules 미포함 업로드 시 병합/압축 해제 다음에 npm install 단계가 실행되어야 한다.
2. node_modules 포함 업로드 시 npm install 단계가 실행되지 않아야 한다.
3. npm install 진행 중 «취소» 시 설치가 중단되어야 한다.
4. npm install 실패 시 어느 단계에서 멈췄는지 단계 목록·로그에서 확인 가능해야 한다.

```
+----------------------------------------------------------------------------------------------------------------------+
```

#### 설명

1. «버전관리» 본문은 좌우 세로 분할 한 줄 레이아웃이다. 가운데 세로 구분선으로 왼쪽·오른쪽 패널을 나눈다.
2. 왼쪽 «설치파일 다운로드»: 현재 접속 서버 전체 압축·초기 세팅용.
3. 오른쪽 «최신 소스 적용»: GNMS 서버 최신 소스 압축을 브라우저 중계로 운영 서버 반영.
4. 좌·우 패널 모두 동일한 폐쇄망/개방망 선택 버튼을 둔다. 폐쇄망(node_modules 포함)이 기본, 개방망 선택 시 압축·적용에서 node_modules 제외.
5. 오른쪽에 «최신소스 적용(라이브러리 업데이트, 업데이트 예정)» 버튼을 «최신 소스 적용» 옆에 둔다. 비활성(준비 중).
6. 한쪽 작업 진행 중 다른 쪽 버튼·버튼·체크는 비활성화한다.
7. «설치 매뉴얼»은 Notion 새 탭. Node·nvm 본문은 화면에 두지 않는다.
8. «이력» 버튼 하나를 제목과 같은 높이·반대편에 둔다. 클릭 시 DEV-DEP-12 플로팅 패널을 연다. 좌·우 패널 안에는 «이력» 버튼을 두지 않는다.

#### 확인사항

1. 좌·우 패널이 한 행에 나란히 보여야 한다.
2. «설치파일 다운로드»·«최신 소스 적용» 버튼이 각각 해당 패널에만 있어야 한다.
3. 폐쇄망/개방망 선택버튼이 좌·우 패널 모두에 동일하게 보이고, 기본값은 폐쇄망이어야 한다.
4. «최신소스 적용(라이브러리 업데이트, 업데이트 예정)» 버튼은 비활성이어야 한다.
5. 재시작 옵션은 오른쪽 패널에만 있어야 한다.
6. «이력» 버튼은 제목 행에 하나만 있어야 하고, 패널 내부에는 없어야 한다.

3. 조회 실패 시에도 공통 이력 테이블에 «최신 소스 적용», 성공=실패, 메시지에 실패 사유를 기록한다.

#### 확인사항

1. 조회 실패 시 페이지 이동·모달 없이 오른쪽 패널 안에서만 실패가 표시되어야 한다.
2. «최신 소스 없음 — 업로드를 먼저 하세요» 등 한국어 안내가 상세에 나와야 한다.
3. 업로드 직후 같은 화면에서 «최신 소스 적용» 재시도 시 조회가 성공해야 한다.
4. 왼쪽 설치 다운로드는 실패 상태와 무관하게 동작해야 한다.
5. 조회 실패도 이력 테이블에 실패로 저장되어야 한다.

### DEV-DEP-11 소스코드 업로드 > 이력 플로팅 패널

```
+----------------------------------------------------------------------------------------------------------------------+
|개발자 모드 [테마변경] [로그아웃] [메인으로]                                                                          |
|v 버전관리              |소스코드 업로더                                              [이력]                          |
| * 소스코드 업로더      |현재 워크스페이스 소스코드를 압축/청크 전송 방식으로 원격 서버에 업로드                      |
|  버전관리              |      +--- 이력              —────────────────── [닫기] +                               |
|> 기타기능              |      | 날짜 [2026-07-08____]  [검색]                       |                               |
|                       |      | 2026-07-08 14:30  성공  … 업로드완료                 |                               |
|                        |      | 2026-07-08 10:15  실패  …  연결 시간 초과           |                               |
|                        |      +----------------------------------------------------------+                               |
+------------------------+---------------------------------------------------------------------------------------------+
```

#### 설명

1. 별도 페이지 이동 없이 소스코드 업로더 제목 행 «이력» 클릭 시 연다. 모달은 플로팅 모달 형태로 구현한다.
2. 상단에 날짜와 «검색»만 있다. «소스코드 업로드» 이력만 조회한다.
3. 목록에는 날짜·시각, 성공/실패, 접속 주소, 메시지가 표시된다. 스크롤 가능.
4. 세 기능 이력은 하나의 공통 테이블에 저장한다. 기능명은 «소스코드 업로드», «설치파일 다운로드», «최신 소스 적용» 세 종이다.
5. 업로드 성공·실패·사용자 중단·DB 불일치 중단 시 이력에 한 건 기록한다.

#### 확인사항

1. «소스코드 업로드» 이력만 조회되어야 한다.
2. 날짜 검색이 동작해야 한다.
3. 실패 행에 메시지(오류·단계 요약)가 보여야 한다.
4. 업로드 종료 시 이력에 기록되어야 한다.

### DEV-DEP-12 버전관리 > 이력 플로팅 패널

```
+----------------------------------------------------------------------------------------------------------------------+
|개발자 모드 [테마변경] [로그아웃] [메인으로]                                                                          |
|v 버전관리              |버전관리                                                      [이력]                         |
|  소스코드 업로더       |GNMS 최신 소스코드 다운로드/덮어쓰기/재시작                                                  |
| * 버전관리             |      +--- 이력         —──────────────────────── [닫기] +                                 |
|> 기타기능              |      | 기능 [전체 ▼]  날짜 [2026-07-08____]  [검색]           |                               |
|                       |      | 2026-07-08 16:00  설치파일…  성공  …                   |                               |
|                        |      | 2026-07-08 15:10  최신 소스…  성공  …                   |                               |
|                        |      +----------------------------------------------------------+                               |
+------------------------+---------------------------------------------------------------------------------------------+
```

#### 설명

1. 별도 페이지 이동 없이 버전관리 제목 행 «이력» 클릭 시 연다. 모달은 플로팅 모달 형태로 구현한다.
2. 상단에 기능 선택(전체·설치파일 다운로드·최신 소스 적용), 날짜, «검색»이 있다. 기본값은 «전체».
3. «전체»는 설치·적용 이력만 포함하고, 소스코드 업로드 이력은 포함하지 않는다.
4. 목록에는 날짜·시각, 성공/실패, 접속 주소, 메시지가 표시된다. «전체»일 때는 기능 열도 구분 표시한다.
5. 설치 다운로드·최신 소스 적용(조회 실패 포함) 종료 시 공통 이력 테이블에 각각 기록한다.

#### 확인사항

1. «전체»는 설치·적용만, «설치파일 다운로드»·«최신 소스 적용» 각각은 해당 이력만 나와야 한다.
2. 기능 선택과 날짜를 함께 적용해 검색해야 한다.
3. 실패 행에 메시지(오류·단계 요약)가 보여야 한다.
4. 세 기능 모두 동일 이력 테이블에 저장·조회 분리가 되어야 한다.
