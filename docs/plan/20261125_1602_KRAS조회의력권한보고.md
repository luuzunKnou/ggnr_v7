## 개발목표

KRAS 조회 이력에 쌓인 개인정보 열람과, 이미 있는 사용자 권한·권한 변경 이력을 한곳에서 기간·사용자 기준으로 묶어 감사할 수 있게 한다. 권한 부여·변경 저장은 새 테이블을 만들지 않고 기존 사용자 권한 관리 이력 체계를 그대로 쓴다.

KRAS 조회 이력 목록은 호출·열람 감사용으로 두고, 권한 현황·변경 요약은 보고서에서 함께 보여 준다. 권한 이력이 비어 있거나 누락된 부분이 있으면 기존 권한 관리·이력 화면·저장 쪽을 보완하고, 조회 이력 테이블에 권한 컬럼을 넣지 않는다.

## 플로우차트

권한 부여·변경 → 기존 권한 관리 이력 저장 → 감사 보고서(권한 요약)

KRAS 조회·개인정보 열람 → 조회 이력 저장 → 감사 보고서(열람 요약) ⇄ 사용자 권한 관리 이력 화면

## 화면설계

### RPT-PERM-01 감사 보고서 — 조건

```
┌─ 개발자 모드 / 시스템관리 ─────────────────────────────────────┐
│ [시스템 사용현황]                                               │
│  · KRAS 조회 이력                                               │
│  · 감사 보고서  ←                                               │
│                                                                 │
│  ┌─ 감사 보고서 ─────────────────────────────────────────────┐ │
│  │ 시작 [____] 종료 [____]  사용자 [____]  부서 [____]        │ │
│  │ [미리보기] [내려받기]                                       │ │
│  └───────────────────────────────────────────────────────────┘ │
└─────────────────────────────────────────────────────────────────┘
```

#### 설명

1. 시스템 사용현황 아래 «감사 보고서» 메뉴로 들어온다.
2. 기간은 필수이고, 사용자·부서는 선택한다.
3. 미리보기는 화면에서 요약표를 보고, 내려받기는 파일로 받는다.
4. KRAS 조회 이력 목록과는 메뉴를 나눈다.

#### 확인사항

1. 기간 없이 미리보기·내려받기가 되지 않아야 한다.
2. KRAS 조회 이력 메뉴와 동시에 같은 패널이 열리지 않아야 한다.
3. 권한만 보거나 열람만 보는 전환 없이, 한 보고서 안에 두 요약이 함께 나와야 한다.

### RPT-PERM-02 감사 보고서 — 미리보기

```
┌─ 감사 보고서 미리보기 ─────────────────────────────────────────┐
│ 기간 · 조건 요약                                                 │
│                                                                 │
│ ■ 개인정보 열람 요약                                             │
│  사용자 | 이름 | 열람 건수 | 최초 열람 | 최종 열람               │
│  ─────┼──────┼─────────┼─────────┼─────────                  │
│  …                                                              │
│                                                                 │
│ ■ 권한·권한 변경 요약                                           │
│  사용자 | 이름 | 현재 권한 요지 | 기간 내 변경 건수 | 최근 변경   │
│  ─────┼──────┼────────────┼────────────┼─────────            │
│  …                                                              │
│                                                                 │
│                    [닫기]  [내려받기]                             │
└─────────────────────────────────────────────────────────────────┘
```

#### 설명

1. 위쪽은 KRAS 조회 이력 중 개인정보 포함 열람만 사용자별로 집계한다.
2. 아래쪽은 기존 권한 관리 이력·사용자 정보로 현재 권한 요지와 기간 안 변경을 보여 준다.
3. 사용자가 지정되면 그 사용자만, 부서만 지정되면 해당 부서 사용자만 포함한다.
4. 열람 이력과 권한 이력은 사용자 아이디로만 맞춘다.

#### 확인사항

1. 개인정보 미포함 조회만 있는 사용자는 열람 요약에 안 나오거나 건수 0으로 구분되어야 한다.
2. 권한 변경이 없는 사용자도 현재 권한 요지는 보여야 한다.
3. 내려받기 파일이 미리보기와 같은 기간·조건·요약을 담아야 한다.

### RPT-PERM-03 사용자 권한 관리 이력 — 보완

```
┌─ 사용자 권한 관리 이력 ────────────────────────────────────────┐
│ 시작·종료 · 대상 사용자 · 작업자 · [검색]                       │
│ 목록 · 수정 상세 보기                                           │
│ (기존 화면 유지, 감사 보고서와 기간·사용자 표현만 맞춤)            │
└─────────────────────────────────────────────────────────────────┘
```

#### 설명

1. 기존 권한 관리 이력 목록·상세 보기 흐름을 유지한다.
2. 감사 보고서에서 쓰는 기간·사용자 조건과 맞도록 조회·표시만 필요 시 보완한다.
3. 권한 부여·변경 시 이력이 빠지는 경로가 있으면 저장 쪽을 보강한다.

#### 확인사항

1. 권한 부여·수정 후 이력 목록에 해당 건이 남아야 한다.
2. 감사 보고서의 권한 변경 건수와 이력 목록 건수가 같은 조건에서 맞아야 한다.
3. KRAS 조회 이력 테이블을 권한 저장에 쓰지 않아야 한다.
