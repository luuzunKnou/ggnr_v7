## 개발목표

관공서·원격 환경에서 대용량 소스 ZIP을 청크 업로드한 뒤 «완료» 단계에서 병합·압축 해제·버전 등록까지 끊기지 않고 마무리되도록 한다. 현재는 청크 수신·병합·최신 압축 해제까지 진행된 뒤 «소스 폴더 메타 등록»에서 대상 폴더가 없어 실패하며, 임시 청크·반쪽 병합본·최신 extracted만 남는 불완전 상태가 발생한다.

수정 범위는 소스 청크 업로드 완료 처리와 소스 폴더 등록 로직이다. 폴더 생성 누락 보완, 압축 해제 대상과 등록 대상 경로 정합, 완료 전 청크·병합 검증, 실패 시 잔여물 정리를 포함한다.

## 플로우차트

업로드 시작 → 청크 수신 → (완료 요청) → 청크 전량 확인 → ZIP 병합 → 크기 검증 → 압축 해제 → 소스 폴더 생성·메타 등록 → 최신 버전 발행 → 임시 작업 정리 → 완료

## 화면설계

## 원인 분석(참고)

| 구분 | 내용 |
|------|------|
| 직접 원인 | 소스 폴더 등록 시 `{소스루트}/{번들폴더}/meta.json` 기록 전 폴더 생성(mkdir) 없음 → ENOENT |
| 설계 불일치 | complete 흐름은 `latest/extracted`에만 압축 해제하고, 등록은 `bundleRoot`(예: `2026-07-07_20260707042105`) 폴더에 메타만 씀. 단건 업로드(`saveSourceUpload`)는 폴더 생성 후 ZIP을 그 안에 풀고 메타 기록 |
| 실패 후 잔여 | complete 중 `registerSourceEntry` 실패 시 이후 `publishLatestVersion`·`cleanupUpload` 미실행 → 청크·병합본 잔존, `latest/extracted`만 존재 |
| 병합 크기 | 병합 직후 `totalSize` 불일치 시 예외. «반토막» 병합본은 이전 실패 run 잔여이거나, init 시 `totalSize` 오입력 가능성(별도 확인) |

## 수정 방향

1. **registerSourceEntry**: `writeFolderMeta` 전 `getFolderPath(folder)`에 `mkdir(..., { recursive: true })` 추가.
2. **completeSourceChunkUpload**:
   - 병합 전 `0..expectedChunks-1` 모든 청크 파일 존재 확인(현재는 파일 개수만 집계).
   - 압축 해제 대상을 `latest/extracted` 단독이 아니라 **번들 폴더**(`getFolderPath(bundleRoot)`)로 통일하거나, extracted 후 번들 폴더로 복사·동기화 후 등록.
   - `publishLatestVersion`과 `registerSourceEntry` 순서·트랜잭션: 등록 실패 시 latest/extracted 롤백 또는 try/finally로 임시 청크 정리 정책 명확화.
3. **오류 메시지**: «소스 폴더 등록» 단계 실패를 한국어로 구분해 UI·로그에 표시.

## 수동 복구(현재 장애)

1. `.upload-work/chunks/{uploadId}` — 해당 세션 청크(재완료 시 사용 가능).
2. `.upload-work/merged/{uploadId}/` — 병합 ZIP(크기가 `session.totalSize`와 일치하는지 확인).
3. `latest/extracted` — 이미 풀린 내용(수정 배포 전까지 임시 참고용).
4. 코드 수정·재배포 후 동일 `uploadId`로 complete 재호출 또는 청크부터 재업로드.
