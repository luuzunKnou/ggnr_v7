## 개발목표

공간분석 메뉴의 «분석결과저장» 이력을 세션이 아니라 데이터베이스에 남긴다. 대상은 단수구역·누수분석이다. 송수경로는 시설을 고르면 경로만 보는 조회용이라 이력을 두지 않는다. 위상검증 오류 목록은 탭에 들어올 때마다 원본에서 다시 계산하므로 이력 테이블에 넣지 않는다.

이미 소스에 있는 이력 헤더·항목·도형 세 테이블을 기준으로 확정한다. 예전 계획의 유형별 분리 테이블은 쓰지 않는다. 수정요청·승인은 이력과 별도 테이블로 두고, 이번 설계 범위는 분석 결과 저장·복원까지다.

기대 결과는 새로고침 후에도 저장한 이력을 다시 열어 지도와 결과 패널을 복원하고, 누수에서 이어간 단수는 출처 이력이 남는 것이다. 데이터베이스에 테이블을 실제로 만드는 적용은 별도 승인 후 진행한다.

## 플로우차트

```
분석실행 → 분석결과저장 → 이력헤더·항목·도형 저장 → 이력목록 → (선택) 지도·패널 복원
누수 저장 → 단수 이어가기 → 단수 저장(출처이력 연결)
송수경로 → (이력 없음) 조회·재생만
위상검증 → (오류목록 저장 없음) → 수정요청은 별도
```

## 화면설계

### MAP-SA-HIST-DB-01 이력 저장 범위

```
┌──────────┬──────────────────────────────────────────────┐
│ 사이드바  │  공간분석                                      │
│ · 단수구역│  · 단수 · 누수 → 분석결과저장 → DB 이력        │
│ · 누수분석│  · 송수경로 → 이력 없음(조회·재생만)           │
│ · 송수경로│  · 위상검증 → 오류목록은 저장하지 않음         │
│ · 위상검증│  · 수정요청·승인은 이력과 다른 저장소          │
└──────────┴──────────────────────────────────────────────┘
```

#### 설명

1. 단수·누수만 «분석결과저장»으로 이력에 남긴다.
2. 송수경로는 정수장·배수지 선택과 경로 재생만 하고 이력을 만들지 않는다.
3. 위상검증은 오류 목록을 이력에 두지 않고, 수정요청이 필요할 때만 별도 요청 저장소를 쓴다.
4. 탐색 케이스 수정요청과 위상 수정요청은 이력 복원과 섞지 않는다.

#### 확인사항

1. 단수·누수 이력만 각 탭 목록에 보여야 한다.
2. 송수경로 탭에 분석결과저장·이력 목록이 없어야 한다.
3. 위상검증 탭에 분석결과저장 이력이 생기지 않아야 한다.

### MAP-SA-HIST-DB-02 이력 헤더·항목·도형

```
┌──────────────────────────────────────────────────────────┐
│ 이력 헤더                                                  │
│  유형 · 제목 · 상태 · 출처이력 · 건수 요약 · 작성         │
│──────────────────────────────────────────────────────────│
│ 이력 항목 (여러 행)                                        │
│  제수변 · 관로 · 필지 · 주소 · 수용가 · 누수위치          │
│──────────────────────────────────────────────────────────│
│ 이력 도형 (여러 행)                                        │
│  스냅점 · 관로선 · 단수면 · 건물면                        │
└──────────────────────────────────────────────────────────┘
```

#### 설명

1. 헤더 한 행이 «분석결과저장» 한 번이다. 유형은 단수·누수다.
2. 단수 상태는 업무 단계(분석완료→설정완료→문자발송 완료→단수중→종료)를 쓰고, 누수는 완료·실패를 쓴다.
3. 누수에서 이어간 단수는 출처 이력 키를 헤더에 남긴다. 송수에서 이어가는 경로는 현재 없다.
4. 항목은 제수변·관로·필지·주소·수용가 등을 행으로 나누고, 가능하면 원본 행 번호도 둔다.
5. 도형은 지도 복원용으로 경위도 좌표계에 두고, 단수면이 여러 개면 순서 번호를 둔다.
6. 단수 사유·기간·문자 초안은 헤더의 조건 저장 칸에 넣는다.

#### 확인사항

1. 저장 후 헤더만으로 유형·건수·출처를 목록에 보여줄 수 있어야 한다.
2. 항목·도형을 합치면 현재 세션 이력과 같은 지도 복원이 가능해야 한다.
3. 출처가 있는 단수는 출처 이력 키가 비어 있지 않아야 한다.

### MAP-SA-HIST-DB-03 수정요청과의 경계

```
┌──────────┬─────────────────────┬────────────────────────┐
│ 구분      │ 쓰는 곳              │ 쓰지 않는 곳            │
│──────────┼─────────────────────┼────────────────────────│
│ 분석 이력 │ 단수·누수 결과       │ 송수·위상 오류 목록     │
│ 탐색요청  │ 연결·절단 케이스     │ 분석 결과 스냅샷        │
│ 위상요청  │ 반전·도형·추가 승인  │ 탐색 기준 학습          │
└──────────┴─────────────────────┴────────────────────────┘
```

#### 설명

1. 분석 이력은 결과를 다시 보기 위한 저장이다.
2. 탐색 수정요청은 연결·절단 거리를 배우는 요청이고, 실행은 슈퍼 계정 중 지정 계정만 한다.
3. 위상 수정요청은 관로·시설 원본을 바꾸기 위한 요청·승인·되돌림용이다.
4. 요청에 분석 이력 키를 남길 수 있게 해, 나중에 «어느 분석에서 낸 요청인지»를 이을 수 있다.

#### 확인사항

1. 이력 저장만으로 관로 원본이 바뀌지 않아야 한다.
2. 수정요청 저장만으로 분석 이력 행이 생기지 않아야 한다.
