## 개발목표

개발자 모드의 데이터관리 그룹에 «레이어 관리» 화면이 통합 허브로 자리한다. 한 화면에서 레이어 전체 목록·업로드·갱신 이력·레이어·필드·코드 설정·인프라 오류 복구를 본다.

본 문서는 위 기능의 현행 구조와 동작을 코드·화면 기준으로 기록하는 독립 스냅샷이다. 화면별 확인사항에 미완·의심 구간을 함께 적어 이후 점검·개선의 기준으로 쓴다.

기타기능 메뉴의 SHP·Excel 전용 업로더는 별도로 남아 있으며, 화면 구성과 절차가 레이어 관리의 업로드와 다르다.

2026-07-06 점검 갱신: «테이블» 열 동작·목록–설정 연동·좌표계 범위는 코드 확인으로 정리했다. 아래 화면별 설명·확인사항이 최신 미완·점검 기준이다.


## 플로우차트

```
개발자 모드 → 데이터관리 → 레이어 관리 → (탭) 목록·SHP이력·Excel이력·설정·오류수정 / (상단) SHP·Excel 업로드
```

#### 설명

1. 데이터관리에서 «레이어 관리»를 선택하면 기본 탭은 «레이어 목록»이다.
2. 상단 우측 «SHP 업로드»·«Excel 업로드»로 업로드 모달을 연다.
3. 목록은 저장소 테이블과 레이어 정의 설정을 합쳐 스키마·출처·그룹·테이블명·한글명·갱신일·스타일 범례·테이블·레이어·스타일 상태·행 액션을 표시한다.
4. 검색·public_layer 표시·오류만 보기 필터와 스크롤 더 불러오기가 있다.
5. 행 끝 «버튼들» 열에는 아이콘 세 개가 왼쪽부터 나열된다. 화면에는 아이콘만 보이고 마우스를 올리면 툴팁으로 구분한다. 와이어프레임은 툴팁 명칭을 `[SHP↓][Excel↓][이력]` 약어로 표기한다.
6. «SHP↓» — SHP 다운로드. 해당 행 테이블의 geometry를 SHP 파일로 내려받는다.
7. «Excel↓» — Excel 다운로드. 해당 행 테이블 데이터를 Excel 파일로 내려받는다. Excel 출처가 아니거나 저장 경로가 없으면 기본 경로로 시도한다.
8. «이력» — 수정 이력 조회. 해당 테이블의 수정 이력 조회 모달을 연다.
9. «테이블» 상태 열은 항상 통과로 표시된다. 목록 행은 저장소 geometry 테이블만 포함하므로, 행이 보이면 테이블은 이미 존재한다는 전제다. 업로드 중 테이블 생성 전에 실패한 건은 목록에 나오지 않는다.
10. «레이어»·«스타일» 열만 게시·스타일 보유 여부를 조회하며, «오류만» 필터도 이 둘 기준이다.
11. 목록과 설정 탭은 역할이 달라 행에서 설정 탭으로 바로 이동하는 동선은 없으며, 당분간 추가하지 않는다.

#### 확인사항

1. 데이터관리·레이어 관리 진입 시 목록 탭이 선택되어 있어야 한다.
2. 레이어·스타일 열이 실제 게시·스타일 보유와 맞아야 한다.
3. «오류만» 필터는 게시·스타일 누락 행만 걸러야 한다.
4. «SHP↓»·«Excel↓»·«이력» 버튼 각각 SHP 다운로드·Excel 다운로드·수정 이력 조회가 동작해야 한다.
5. 업로드 완료 후 목록 갱신일·상태가 반영되어야 한다.

#### 설명

1. «SHP 업데이트 이력» 탭에서 배치 단위 업로드·후처리 기록을 페이지로 본다.
2. 상단 툴바는 «총 N건»이 왼쪽, «새로고침»이 오른쪽에 정렬된다.
3. 배치 행의 `[v]`·`[>]`로 펼침·접힘을 표시한다. 한 배치만 펼칠 수 있으며, 펼친 행 아래에 레이어별 하위 이력이 들여쓰기된 표로 붙는다.
4. 배치 행을 펼치면 레이어별 결과·건수·업데이트 내용·«동기화» 액션이 하위 표로 보인다.
5. «동기화»는 변경 대기 상세 모달을 연다.
6. 동기화 호출 시 파일명 기준 식별과 저장소 테이블명이 어긋나면 상세 건수가 비어 보일 수 있다.

#### 확인사항

1. SHP 업로드 완료 후 이 탭으로 전환되면 방금 작업 배치가 보여야 한다.
2. 배치 행을 클릭하면 `[>]`가 `[v]`로 바뀌며 하위 레이어 이력이 보이고, 다른 배치는 접혀야 한다.
3. 변경·동기화 대기 행에서 «동기화» 시 상세 건수가 0만 나오면 안 된다.
4. 동기화 처리 후 목록의 결과·내용 문구가 갱신되어야 한다.

#### 확인사항

1. 레이어 선택 시 해당 필드 목록이 로드되어야 한다.

3. 상세보기 전체 해제 후 저장 시 모든 필드 상세보기가 꺼져야 한다.

1. 4단계 «결과»에서 작업명·좌표계·경로 요약과 레이어별 최종 결과 표를 본다.
2. 요약에 레이어 수·성공·실패·정합성 처리 건수가 표시된다.
3. 표 열은 레이어·구분·Table·Layer·Style·Define·DB행·정합성 처리·결과·비고이다.
4. «완료» 시 모달이 닫히고 SHP 업데이트 이력 탭으로 전환된다.
5. 좌표계는 서버가 .prj·파일명·폴더명 순으로 결정해 DB 적재 시 5181로 변환한다. 정사영상 관리식 좌표계 선택 모달은 미구현이다.

#### 확인사항

1. 4단계 진입 시 결과 집계·표가 로드되어야 한다.
2. 성공·실패·정합성 요약이 실제 처리와 맞아야 한다.
3. «완료» 후 SHP 업데이트 이력 탭에 이번 배치가 보여야 한다.
4. .prj·파일명·폴더명으로 좌표계가 정해지는 SHP는 모달 없이 적재되어야 한다.

#### 설명

1. «Excel 업로드»를 누르면 네 단계 마법사 모달이 열리고 뒤 화면은 어둡게 보인다. 제목은 «Excel 파일 업로드 - 단계명 (n/4)» 형식이다.
2. 1단계 «01. 파일 업로드»: «파일 선택»·«서버에서 선택», 파싱·검사 중 안내. «테이블 한글명·영문명» 입력. «동일 테이블 존재 여부»에서 «layer 테이블 확인». «업로드 처리 방식» 라디오(일반·개발행위대장·점용대장·안동 도로점용대장).
3. 2단계 «02. 지도에 표현할 값 선택»: 타이틀 행 수, 폴리곤/포인트, 필지 주소 열(통합 또는 시도·시군구·읍면동·리·지번 구분), 별도 지적·물건지 테이블 생성 옵션. 처리 방식에 따라 일부 고정.
4. 3단계 «03. 영문·한글 파일명 및 필드명»: 기존 테이블 DIFF, Key 설정, 필드별 영문·한글명·목록·검색·Key 표 편집.
5. 4단계 «04. 데이터 처리»: 진행률·처리 로그. 완료·오류 시 «닫기»로 종료 후 Excel 이력 탭 전환.
6. SHP 업로드와 화면 구성·단계 이름·입력 항목이 다르다.

#### 확인사항

1. 파일·서버 선택 후 파싱 오류가 있으면 1단계에서 안내가 나와야 한다.
2. «layer 테이블 확인» 결과가 신규/기존에 맞게 표시되어야 한다.
3. 처리 방식별로 2~4단계 필수 항목이 달라지며, 미충족 시 «다음»이 비활성이어야 한다.
4. 4단계 처리 완료 후 Excel 업데이트 이력 탭에 이번 작업이 남아야 한다.
5. 완료 후 레이어 목록 갱신일·오류수정 배지가 갱신되어야 한다.
