2026-10-29 | 213am | 민원관리 분류UI complaint 테이블 연동

## 개발목표

지도 «민원관리» 분류UI에서 업무 탭(전체·상수·급수 또는 전체·하수·준설)에 맞춰 DB의 민원 대장 테이블 목록을 조회한다. «전체»는 현재 상·하수도 시스템 범위만 포함한다. 기존UI는 공통 접수 테이블 목록을 그대로 둔다.

## 플로우차트

지도 → 민원관리 → (분류UI) → 업무 탭 → 대장 테이블 목록 → 상세·등록

## 화면설계

### MAP-COMP-CAT-01 민원관리 분류UI

```
┌──────────────────────────────────────────┐
│ [≡]  민원관리              [분류UI][닫기] │
│      전체 N건 (분류 UI)                    │
├──────────────────────────────────────────┤
│  전체 │ 상수 │ 급수   (상수도 시스템 예)   │
├──────────────────────────────────────────┤
│ [검색]                                    │
│ (상태 필터 칩)                             │
├──────────────────────────────────────────┤
│  #접수 #상수 #123 …                       │
│  … 목록 …                                 │
└──────────────────────────────────────────┘
```

#### 설명

1. 분류UI일 때 목록은 접수 공통 테이블이 아니라 민원 대장 테이블에서 읽는다.
2. URL 시스템이 상수도면 탭은 전체·상수·급수만, 하수도면 전체·하수·준설만 보인다.
3. 행의 업무 배지는 대장 테이블 종류(상수·급수·하수·준설)로 표시한다.
4. 행 선택·등록은 상하수도 민원 상세·등록 화면과 동일하게 연다.
5. 기존UI 전환 시 기존 접수 목록·상세 동작을 유지한다.

#### 확인사항

1. 상수도에서 하수·준설 탭이 보이지 않아야 한다.
2. 하수도에서 상수·급수 탭이 보이지 않아야 한다.
3. 분류 «전체»에 반대 시스템 민원이 섞이지 않아야 한다.
4. 기존UI에서 접수 목록이 이전과 같아야 한다.
