# 작업요청서

2026-06-30 | luuzunKnou | 레이어 업로드 절차 확인 및 부족한 기능 개선

## 배경

지도 레이어(SHP·엑셀 등)를 올려 DB·지도 서버·레이어 정의까지 연결하는 절차가 여러 단계로 나뉘어 있다. 폴더 단위 일괄 업로드·갱신 시 단계별 완료 여부를 확인하기 어렵고, 기존 데이터와 SHP row를 Key 기준으로 맞춰 반영할지 결정하는 절차·검증이 부족하다. 중간 실패 시 어디서 막혔는지 파악이 늦어지는 경우가 있어, 현행 화면·기능을 점검하고 안내·재시도·이력·상태 표시·동기화 규칙 등을 보완해 업무에 쓸 수 있는 수준으로 맞춰야 한다.

## 활용

1. GIS·DB 담당자가 **폴더 단위** SHP를 업로드해 지도에 레이어를 신규 반영·갱신할 때 단계별 진행을 확인한다.
2. 기존 레이어에 SHP를 다시 올릴 때 **Key 기준 row 비교**로 신규·변경·삭제 후보를 확인하고 선택 반영한다.
3. 엑셀 기반 레이어 등록·갱신 업무와 절차·용어를 맞춰 담당자가 혼동하지 않게 한다.
4. 운영·시연 전 절차 리허설(업로드 → 반영 → 지도 확인) 체크리스트 근거로 쓴다.

## 필요 기능

1. **폴더 기반 레이어 업로드** — SHP 폴더·다파일 업로드, 업무 순서(업로드 → DB 반영 → 지도 서버 → define 등)별 **완료·진행·실패·건너뜀** 표시, 단계별 성공·실패 사유 안내, 실패 시 **해당 단계부터 재실행**

2. **레이어 상태 점검·누락 작업 재실행** — DB·지도 서버·define 간 불일치 확인, 누락된 작업(테이블 생성, GeoServer 레이어 생성, default style 생성, define layer·field·code 생성) **재실행**.

3. **SHP 다운로드** — 레이어·테이블 기준 SHP 내려받기.

4. **이력 조회** — 레이어 업로드·동기화 **이력**(언제·무엇을·몇 건 반영했는지) 조회.

5. **컬럼·타입 검증** — 기존 테이블과 **컬럼 또는 타입**이 다른 경우 사전 검증. **컬럼 구성이 다르면 업로드 불가.**

6. **Key 기준 row 단위 동기화** — 레이어 업로드 시 기존 DB row와 SHP row를 **Key**로 맞춰 **속성값·geom**이 기존과 다른지 검사한 뒤 row별 반영 여부를 결정한다.
   - case1. DB row 있음 / SHP row 없음 — 삭제 여부 확인 후 삭제. **사용자가 추가한 row**는 유지.
   - case2. DB row 없음 / SHP row 있음 — 충돌 없음, **신규 row** 추가.
   - case3. 양쪽 Key 존재·값 상이 — 데이터를 비교해 **최신 데이터 선택** 또는 **DB 유지** 결정.
   - Key·값 모두 동일한 row는 변경 없음.

7. 엑셀→DB·레이어 생성 마법사와 SHP 업로드 절차 간 **용어·단계 표현** 통일.

8. 화면설계시 데이터 comflict 모달 구성 및 해결 절차에 대한 설계 첨부.
