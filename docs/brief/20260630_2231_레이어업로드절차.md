# 작업요청서

2026-06-30 | luuzunKnou | 레이어 업로드 절차 확인 및 부족한 기능 개선

## 배경

지도 레이어(SHP·엑셀 등)를 올려 DB·지도 서버·레이어 정의까지 연결하는 절차가 여러 단계로 나뉘어 있다. 담당자가 단계별로 무엇이 끝났는지 확인하기 어렵고, 중간 실패 시 어디서 막혔는지 파악이 늦어지는 경우가 있다. 현행 화면·기능을 점검하고 빠진 안내·재시도·이력·상태 표시 등을 보완해 업무에 쓸 수 있는 수준으로 맞춰야 한다.

## 활용

1. GIS·DB 담당자가 신규·갱신 SHP를 업로드해 지도에 레이어를 반영할 때 단계별 진행을 확인한다.
2. 엑셀 기반 레이어 등록·갱신 업무에서 업로드 후 테이블·레이어·스타일·속성 정의까지 이어지는 흐름을 한 화면에서 추적한다.
3. 레이어 상태 점검·동기화·이력 조회로 «올렸는데 지도에 안 보임» 민원을 줄인다.
4. 운영·시연 전 절차 리허설(업로드 → 반영 → 지도 확인) 체크리스트 근거로 쓴다.

## 필요 기능

1. 레이어 업로드 **전체 절차**를 업무 순서(업로드 → DB 반영 → 지도 서버 반영 → 레이어 정의·속성 연동 등)로 정리·표시하고, 각 단계 **완료·진행·실패·건너뜀** 상태를 사용자가 볼 수 있어야 한다.
2. 단계별 **성공·실패 사유** 안내와, 실패 시 **해당 단계부터 재실행** 또는 **전체 재시도**가 가능해야 한다.
3. SHP 폴더·파일 업로드, 기존 테이블과 비교·동기화, 일괄 처리(테이블·레이어·스타일·정의) 흐름이 끊기지 않고, 중간 실패 시 이후 단계가 잘못 진행되지 않아야 한다.
4. **레이어 업데이트 이력**(언제·무엇을·몇 건 반영했는지)을 조회할 수 있어야 한다.
5. 레이어 상태 화면에서 DB·지도 서버·정의 테이블 간 **불일치**를 확인하고, 부족한 단계(레이어 미생성·스타일 미적용 등)를 보완할 수 있어야 한다.
6. 엑셀→DB·레이어 생성 마법사와 SHP 업로드 절차 간 **용어·단계 표현**을 맞춰 담당자가 혼동하지 않게 해야 한다.
7. 절차 확인 후 **지도에서 레이어 on·식별·속성**까지 스모크 확인할 수 있는 테스트 항목을 plan·report에 남길 수 있어야 한다.

## 참고·제약

- dev 메뉴 SHP 업로드·레이어 상태·업데이트 이력·엑셀 마법사·레이어 속성·정보 관리 등 **기존 화면·기능을 우선 점검·개선**한다. 전면 재설계는 제외.
- GeoServer·DB·defineLayer 연동은 환경(프로젝트·dev/demo/prod)별 설정 차이를 plan에서 구분한다.
- 대용량·다파일 일괄 업로드 시 진행률·중단·재개 요구는 2차로 분리 가능.
- DB 스키마 push·migrate는 사용자 명시 요청 전까지 실행하지 않는다.
