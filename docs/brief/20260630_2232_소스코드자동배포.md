# 작업요청서

## 배경

**GNMS**는 시연 서버(192.168.126.1)의 **공간누리 통합관리 솔루션**으로, 최신 소스 등록·버전 관리 중앙 역할을 한다. **전산실 앱 서버(192.168.126.55)** 는 폐쇄망이라 GNMS와 직접 통신하지 못한다.

배포는 **두 경로**로 나뉜다.

- **최초 세팅** — 「설치파일 다운로드」로 ZIP을 받은 뒤, **파일 복사**로 192.168.126.55에 반영·기동한다 (80포트 중계 아님).
- **기동 후 패치** — 담당자 PC **브라우저(Client)** 가 ggnr dev «버전관리» **「최신 소스 적용」** 으로 GNMS에서 ZIP을 받아 **80포트** HTTP로 서버에 중계·적용·재기동한다.

ggnr dev 화면:

- GNMS 최신 소스 등록 — «버전관리» › «소스코드 업로드»
- 초기 설치 — «버전관리» › «버전관리» › 「설치파일 다운로드」 → **파일 복사**로 서버 세팅
- 기동 후 패치 — «버전관리» › «버전관리» › 「최신 소스 적용」 → Client **80포트** 중계

아래 7단계를 검증하고 오류를 수정한다.

## 활용

1. 개발·운영 담당자가 GNMS에 소스를 올리고, 전산실 서버 **최초 세팅(파일 복사)**·**기동 후 패치(80포트)**·재기동까지 수행한다.
2. 패치 시 Client 중계 진행·로그로 성공 여부를 확인한다.
3. 실패 시 등록·다운로드·복사(또는 중계)·적용·기동 중 어디서 막혔는지 파악해 재시도한다.

## 필요 기능

1. **초기 설치** — **«버전관리» › «버전관리» › 「설치파일 다운로드」** — 전체 ZIP 수신.
2. **서버 최초 세팅** — ggnr dev UI 없음. ZIP을 **파일 복사**로 192.168.126.55 워크스페이스에 반영.
3. **서비스 기동** — ggnr dev UI 없음. 반영 후 접속·헬스 확인 가능.
4. **기동 실패 시** — 1~3단계(다운로드·복사·기동) 경로 점검·수정으로 반복 성공.
5. **GNMS 업로드** — **«버전관리» › «소스코드 업로더» › 「현재 코드 자동 업로드」** — 192.168.126.1에 최신 ZIP 등록·조회·다운로드. 오류 수정.
6. **기동 후 업데이트** — **«버전관리» › «버전관리» › 「최신 소스 적용」** — Client **80포트** 중계·적용, 
7. **자동 재기동** — **«버전관리» › «버전관리»** 패널 **「적용 후 서버 재시작」** 체크·재시작 방식(process.exit / 명령 실행 / 재시작 안 함) — 패치 후 실행 검증, 실패 시 수정·안내.

공통: 진행·로그·실패 안내, 청크 업로드·재개(패치 경로), `.env`·런타임 등 민감·대용량 제외.

## 참고·제약

- 테스트: GNMS 192.168.126.1, 앱 서버 192.168.126.55.
- **최초 세팅 = 파일 복사**, **기동 후 패치 = Client 80포트 중계** — 혼동하지 않도록 UI·문구·테스트도 구분.
- 기존 소스코드 업로더·버전 관리·GNMS 중계·청크 업로드·적용 API 우선 점검·수정 (전면 재설계 제외).
- DB migrate·스키마 자동 적용은 사용자 명시 요청 전까지 배포에 포함하지 않음.
