# 작업요청서

2026-11-13 | dev.strcat | 데이터관리 · 공공·수급 인수 검수

## 배경

공공에서 받은 자료와 수급(또는 기존 보유) 자료를 맞춰 보고 인수·갱신 범위를 판단해야 한다. 지금 구현된 비교 화면은 기술 단계·숫자 나열 중심이라, «무엇이 다른지·인수해도 되는지»가 한눈에 안 들어온다. 오류수정·정합성과도 목적이 다르다. 검수용 대조 리포트로 다시 설계한다.

## 활용

1. 데이터 담당자가 공공본과 수급본을 올려(또는 레이어를 골라) 인수 전 차이를 본다.
2. 건수·항목·위치·내용 중 어디가 어긋났는지 요약으로 먼저 파악한다.
3. 차이 목록을 엑셀로 넘겨 검수·인수인계에 쓴다.
4. 시스템 반영·동기화는 하지 않는다. 보기와 내보내기만 한다.

## 필요 기능

1. 개발자 도구 «데이터관리»에 «공공·수급 비교»(가칭) 메뉴를 둔다. (기존 «레이어비교»는 이 방향으로 교체)
2. 양쪽 역할을 고정한다. 왼쪽 «공공 데이터», 오른쪽 «수급 데이터». 각각 DB 레이어 또는 파일(임시)을 고를 수 있다. 다만 최소 한쪽은 DB 레이어여야 한다. 파일↔파일만은 하지 않는다.
3. 파일은 임시로만 올리고 정의·지도서비스·목록에 남기지 않는다. 비교가 끝나면 임시본을 정리한다.
4. 비교 전에 «짝 짓는 방법»만 짧게 고른다. (식별키 / 위치 / 키+위치). 컬럼 이름 맞추기는 자동·후보를 한 표로 보여 주고, 애매한 것만 확인한다.
5. 결과는 «검수 리포트» 한 화면이다. 맨 위 판정 요약(같음·주의·차이 큼)과 한 줄 결론, 그 아래 영역별 카드(규모·항목·위치·내용), 필요 시만 상세 목록을 펼친다.
6. 상세에는 사람이 읽을 식별값(키·주요 명칭)과 «공공 값 / 수급 값» 대비만 보여 준다. 기술 식별자·내부 행번호는 화면 기본에 두지 않는다.
7. 내보내기는 검수용 엑셀(요약 시트 + 차이 시트)을 기본으로 한다.
8. 반영·저장·동기화 버튼은 두지 않는다. 지도 미니맵은 1차에서 넣지 않는다.

## 참고·제약

- 기존 «레이어비교» 구현은 폐기·교체 대상으로 본다. 메뉴·문구·결과 구성을 업무 검수 관점으로 다시 잡는다.
- 정합성(반영 전제)·오류수정(설정 누락)과 역할을 분리한다.
- 위치 짝은 공공 쪽 도형 종류(점·선·면) 기본값을 쓰고, 격자 스냅은 쓰지 않는다.
- «같다»의 기준은 화면에서 짧게 안내한다. (건수·항목·짝·내용이 모두 맞으면 같음, 일부만 다르면 주의, 짝이 거의 안 맞으면 차이 큼)
