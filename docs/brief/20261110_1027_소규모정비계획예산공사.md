# 작업요청서

2026-11-10 | dev.strcat | 소규모 공공시설 정비계획 분석·마스터 DB·화면 설계서, 마스터 스키마 SQL

## 배경

1. 소규모 공공시설관리 시스템에 후보지·안전점검까지 화면이 있으나, 위험시설을 어떤 순서로 얼마를 들여 정비할지 정하는 정비계획과, 그 계획을 예산·공사로 집행하고 실적을 관리하는 업무가 없다.
2. 정비계획 수립 때 사업비·보상비·우선순위 평가를 용역 보고서와 고시 단가로 손으로 계산하고 있어, 기준이 바뀌거나 시설이 추가될 때마다 다시 계산해야 한다.
3. 안전점검 대상이 매년 일반·관리 시설로 정해지는데 지금은 사람이 하나씩 등록하고, 점검 결과로 위험시설이 되는 흐름과 사업발주 근거자료 출력이 없다.

## 활용

1. 안전점검 담당자가 연초에 해당 연도 점검 대상(일반·관리 시설)을 자동으로 받아 점검을 등록하고, 점검 결과로 위험시설을 확정한다.
2. 안전점검 담당자가 점검 용역 발주 시 대상 목록과 근거자료를 기준일 기준으로 출력하고, 나중에 같은 기준일 목록을 다시 연다.
3. 정비계획 담당자가 위험시설마다 정비내용·사업비·보상비·평가 점수를 단계별로 채워 우선순위와 1·2단계, 연차 배분을 정한다.
4. 정비계획 담당자가 중기계획 명세서를 엑셀로 내려받아 보고·협의에 쓴다.
5. 예산 담당자가 연도별 예산을 등록·배정·집행하고, 공사 담당자가 공사대장과 준공 서류를 관리해 정비율과 계획 대비 실적을 본다.

## 필요 기능

1. 안전점검 대상은 일반·관리 시설을 자동으로 넣고, 그 밖의 시설(위험시설 재점검 등)은 «시설 등록»으로 추가한다.
2. 점검 결과에 평가구분(일반·관리·위험)을 남기고, 최근 점검의 평가구분이 시설 구분에 자동 반영된다. 위험으로 바뀌면 위험시설 지정일이 채워진다.
3. 안전점검에서 점검 대상 목록(엑셀)과 사업발주 근거자료(표지·개요·선정 기준·대상 목록·전년 대비 변동)를 내려받고, 출력한 기준일 목록을 다시 볼 수 있다.
4. 정비계획 목록은 중기계획 명세서 형태(순위·시설명·유형·위치·사업량·사업비·단계·연차·사업효과·상태·완성도)로 보이고, 엑셀로 내려받는다.
5. 시설별 분석은 개요·정비내용·사업비와 보상비·기본평가·부가평가·결과 순서로 진행하고, 값마다 자동·기본값·수기·실적·미입력 출처를 보여 준다. 미입력이 있어도 계산 가능한 만큼 계산하고 완성도와 «참고용 추정치»를 표시한다.
6. 순위는 군 전체 통합으로 총점·동점 규칙에 따라 정하고, 1단계 기준(순위 컷 등)과 연차 배분을 설정값으로 정한다. 상태는 추정→검토→확정→진행→완료이며 확정 후 수정은 새 버전으로 남긴다.
7. 예산·공사는 연도별 통계, 예산 등록·배정·집행, 공사대장(계약·대상 시설·준공·첨부)을 관리하고, 준공 시 정비율과 실제 공사비를 정비계획에 반영한다.
8. 단가·지원율·가중치·배점 구간·보상배율·단계 기준은 기준값 자료에서 읽고, 정비계획 화면에서 적용한 근거(고시 번호·단가 출처)를 볼 수 있다.

## 참고·제약

1. 이번 단계는 지금 후보지·안전점검처럼 예시 자료로 화면을 먼저 만든다. 기준값은 마스터 스키마 SQL의 시드 값을 그대로 옮겨 쓰며, 실제 DB 생성·적재는 담당자가 직접 한다.
2. 진행 순서: 후보지·안전점검 수정 → 정비계획(시설별 분석·목록) → 예산·공사. 기준값 편집 화면은 나중에 만들고, 이번에는 정비계획 안에서 산출근거 보기만 둔다.
3. 설계서 5장의 확인 필요 항목(배점 체계, 사망·부상 반영 방식, 공시지가·보상배율 적용, 최종순위 산식, 1단계 기준, 공종 정식 단가 등)은 임의로 확정하지 않고 설정값으로 남긴다.
4. 공종 단가 대부분은 보고서에서 역산한 임시 단가이므로 화면에 «임시 단가»로 표시한다.
5. 기존 시설 대장(후보지)은 시설 식별자로만 연결하고 구조는 바꾸지 않는다.
6. 울진(건설통합행정) 사이트에만 켠다.
