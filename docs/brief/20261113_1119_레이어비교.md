# 작업요청서

2026-11-13 | dev.strcat | 데이터관리 · 공공·수급 데이터 대조

## 배경

공공에서 받은 데이터와 수급·기존 레이어 데이터를 한눈에 맞춰 보고 싶다. 지금은 오류수정(설정 누락)이나 정합성(반영 전제)으로는 대등한 대조가 어렵다. 개발자 도구에서 두 소스를 골라 구조·위치·내용 차이를 리포트로 남길 필요가 있다.

## 활용

1. 데이터 담당자가 공공본·수급본을 인수 전에 건수·컬럼·위치·속성 차이를 확인한다.
2. 기존 DB 레이어와 다른 DB 레이어(또는 가져온 파일)를 대조해 갱신 범위를 가늠한다.
3. 검수·인수인계용으로 요약과 불일치 목록을 엑셀·CSV로 넘긴다.
4. 정합성과 달리 DB·레이어에 반영하지 않고 읽기 전용으로만 쓴다.

## 필요 기능

1. 개발자 도구 «데이터관리»에 «레이어비교» 메뉴를 둔다.
2. 기준은 항상 기존 DB 레이어(테이블)에서 고른다.
3. 대조 대상은 (가) 다른 DB 레이어 또는 (나) 첨부 파일(엑셀·SHP·ZIP·DBF 등)이다. 파일↔파일은 하지 않는다.
4. 첨부 파일은 임시 테이블로만 올리고, 레이어 정의·지도 서비스·목록에는 남기지 않는다. 비교가 끝나면 임시 테이블을 정리한다.
5. 1단계(구조): 건수·도형 종류·좌표계, 컬럼 A만/B만/양쪽, 컬럼 매칭(영문 동일 자동 · 한글명 동일 후보·확정 · 둘 다 다르면 매칭 안 함 · 한글만 있으면 한글 동일만 · 타입만 다르면 타입 불일치 표시).
6. 2단계(공간): 짝 짓기용 키 칸은 비교 시 사용자가 고른다. 키를 고르면 키 우선. 키를 고르지 않았고 도형이 있으면 위치 짝을 맺는다. 위치 방식은 정합성의 격자 스냅이 아니라, 기준 레이어 도형 종류(점·선·면)에 따른 기본값으로 한다. 도형이 없으면 키만으로 짝을 맺거나 공간 단계를 생략한다.
7. 3단계(속성): 짝이 난 행만 매핑 컬럼별 동일/상이, 컬럼별 불일치 건수·샘플, 코드·목록은 값 집합(서로 있는/없는 값)만 1차로 비교한다. 행 단위 코드 의미 매핑은 다음 단계로 미룬다.
8. 결과: 요약 카드(건수 A/B, 일치·A만·B만, 속성 불일치), 컬럼 매핑표, 공간 요약(벤다이어그램식 숫자), 속성 불일치 목록(다른 칸만 강조), 엑셀·CSV 내보내기. 미니맵과 반영 버튼은 두지 않는다.

## 참고·제약

- 정합성·오류수정과 메뉴·역할을 분리한다. 비교는 조회·리포트만 한다.
- 공간 짝짓기는 기준 레이어 도형 종류별 기본 허용값을 쓴다. 격자 스냅은 쓰지 않는다. 미니맵은 1차에서 제외한다.
- 대조 파일이 도형 없는 표(엑셀·DBF)이면 공간 단계 없이 키·속성 중심으로 진행한다.
- 대용량은 요약·샘플 위주, 전체 목록은 필요 시 비동기로 둔다.
