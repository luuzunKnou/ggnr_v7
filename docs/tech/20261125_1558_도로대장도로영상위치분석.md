# 기술문서 — 도로대장 도로영상 위치 분석

2026-11-25 | dev.strcat | 도로대장 «도로영상» 위치 맞춤·지도 연동

---

## 1. 개요

도로대장에 첨부된 360° 도로영상에는 촬영 GPS가 없다. 본 기능은 영상 화면의 회전·전진과 대장 노선 선형(굽이·교차·분기)을 맞춰 **영상 시각 ↔ 노선 위 위치**를 구하고, 재생 중 지도에 차량 표식을 동기화한다.

| 항목 | 내용 |
|------|------|
| 진입점 | 지도 → 도로대장 상세 → «도로영상» |
| 목적 | 위치 기록 없는 도로영상을 노선에 자동·수동으로 맞춤 |
| 분석 방식 버전 | **15** (`ROAD_VIDEO_ANALYZER_VERSION` / Python `ANALYZER_VERSION`) |
| 좌표계 | 분석 내부 미터 좌표 SRID **5181**, 화면 표시는 경위도 |

---

## 2. 전체 구조

GPS가 없는 360° 영상을 **대장 노선 선형**에 붙이는 파이프라인이다. 화면은 결과만 읽고, 무거운 분석은 서버 스케줄러 + Python이 담당한다.

### 2.1 한눈에 보는 흐름

```
① 첨부 저장
   file_data/a0020000/{roadKey}/*.mp4
        │
② 도로대장 상세 «도로영상» 열기
   ├─ 일반 계정: getRoadVideoTrack 만 (기존 결과 또는 시간비율)
   └─ 슈퍼(su·admin): requestRoadVideoTrack → requested_at 기록
        │
③ 서버 스케줄러 (1분, 동시 1건)
   ├─ 노선 선형(5181) + 교차시설 면 + 분기점 + 수동점 수집
   ├─ 상행1·2 / 하행1·2 는 같은 방향끼리 이어 붙여 1회 분석
   └─ Python: 모션 측정 → DTW 맞춤 → (분기·수동 보정) → JSON
        │
④ DB 저장
   road_video_track (영상 메타) + road_video_anchor (1초 위치)
        │
⑤ 화면 동기화
   재생 시각 ⇄ 노선 m ⇄ 지도 자동차 / 자동차·노선 클릭 → seek
```

### 2.2 계층별 역할

| 계층 | 담당 | 하지 않는 것 |
|------|------|----------------|
| UI (`RoadLedgerVideoSync` 등) | 창·재생·지도 차·수동점 UI, 대기 중 재조회 | 분석 실행 |
| Service (`roadVideoTrackService`) | 조회·요청·수동점 CRUD | Python 호출 |
| Scheduler (`roadVideoTrackScheduler`) | 요청 큐 소비, 입력 JSON 작성, spawn, 결과 저장 | 화면 API |
| Lib (`roadVideoTrack`) | 테이블 ensure, 노선/교차/분기/파일 검증 | 영상 디코딩 |
| Python (`pipeline.road_video_track`) | OpenCV 모션 + DTW + 보정 | DB 직접 접근 |

### 2.3 맞추는 데 쓰는 재료

| 재료 | 출처 | 쓰임 |
|------|------|------|
| 360° 영상 | 첨부 폴더 | 회전·전진·정면각 시계열 |
| 노선 선형 | 도로대장 geom (여러 조각이면 끝점 이어 붙임) | DTW 목표 경로 |
| 교차시설 면 | `a0080000` ∩ 노선 | 로터리 한 바퀴 = 구역 안 제자리 회전 |
| 도로중심선교점 | `a9990001` | 분기 m + 회전 허용 원형 구역 |
| 파일명 상행/하행 | 파일명 문자열 | 정·역방향 힌트, 분할 묶음 |
| 수동 기준점 | `road_video_landmark` (su) | DTW 뒤 시각·거리 강제 보정 |

분석이 끝나기 전·실패 시에는 위 결과 없이 **시간 ÷ 영상길이 × 노선길이** 비율로만 지도에 올린다(하행은 끝→시작).

## 3. 첨부·파일 규칙

### 3.1 저장 위치

| 항목 | 값 |
|------|-----|
| 레이어 ID | `a0020000` (도로대장 요약 첨부) |
| 경로 | `{GGNR_DATA}/file_data/a0020000/{roadKey}/{fileName}` |
| roadKey | 노선 `rdid`, 없으면 `ogc_fid` (폴더명 = 화면·DB의 노선 키) |
| 허용 확장자 | `.mp4` / `.mov` / `.webm` (대소문자 무시) |
| 숨김 파일 | 서비스 첨부 숨김 규칙에 해당하는 이름은 목록·분석에서 제외 |

경로·파일명은 서버에서 세그먼트/basename 안전 검사 후만 `stat`한다. 없거나 영상이 아니면 분석 요청은 실패로 정리된다.

### 3.2 파일명으로 방향·분할 판정

파일명에 한글 **상행** / **하행**이 들어가는지로 그룹을 나눈다.

| 파일명 예 | 그룹 | 분할 번호 | 분석 시 선호 방향 | 재생 탭 |
|-----------|------|-----------|-------------------|---------|
| `…상행.mp4`, `…상행1.mp4` | up | 1 (숫자 없으면 1) | `forward` = 노선 geom 시작→끝 | «상행» |
| `…상행2.mp4` | up | 2 | 동일 | «상행»에 이어 재생 |
| `…하행1.mp4` | down | 1 | `reverse` = 끝→시작 | «하행» |
| 상·하행 없음 | other | 1 | 힌트 없음(정·역 둘 다 시도) | 파일명 기준 단독 |

- 분할 번호: `상행\s*(\d+)`, `하행\s*(\d+)` 정규식.
- **같은 노선 폴더**에서 같은 그룹(상행끼리 / 하행끼리)은 번호 오름차순으로 **한 번에 이어 붙여 분석**한다.  
  예: 상행1 요청이 잡혀도 폴더에 상행2가 있으면 `videos: [상행1, 상행2]`로 돌리고, 결과를 각 파일 로컬 시각으로 나눈 뒤 파일마다 track/anchor를 저장한다.
- 화면 재생도 같은 규칙으로 «상행»·«하행» 재생 목록을 묶는다.

### 3.3 업로드·재분석 때 주의

- 마지막 수정 후 **2분 이내** 파일은 “올리는 중”으로 보고 스케줄러가 건너뛴다.
- 분석 결과는 **파일 크기 + 수정시각**을 지문으로 저장한다. 파일이 바뀌면 슈퍼가 열 때 다시 요청된다.
- 분석 방식 버전(`analyzer_ver`)이 코드보다 낮아도 재요청된다.

## 4. 분석 요청·스케줄러

### 4.1 왜 “요청제”인가

초기에는 첨부 폴더를 주기적으로 훑어 미분석 영상을 돌렸다.  
지금은 **슈퍼가 실제로 열어 본 영상만** 큐에 넣어, 불필요한 전수 분석과 구버전 자동 재분석을 줄인다. 일반 사용자는 이미 끝난 결과(또는 시간 비율)만 본다.

### 4.2 요청이 남는 조건 (`requestRoadVideoTrack`)

호출 주체: 슈퍼 계정(`su`·`admin`). 그 외는 no-op.

| 조건 | 동작 |
|------|------|
| track 행 없음 / 결과 없음 | `requested_at`·`requested_by` 기록 |
| `file_size`·`file_mtime`이 현재 파일과 다름 | 재요청 |
| `analyzer_ver` < 현재(15) | 재요청 (알고리즘 업그레이드) |
| UI «다시 분석» (`force`) | 결과 있어도 재요청 |
| 이미 최신 done이고 파일·버전 동일 | 요청 안 남김 |

재분석이 끝나기 전까지 **이전 done 앵커는 그대로** 화면에 쓴다. 요청만 걸린 상태(`queued`)는 `requested_at IS NOT NULL`로 표시한다. 영상 창은 대기 중 약 **8초**마다 `getRoadVideoTrack`을 다시 친다.

### 4.3 스케줄러 동작

- 등록: 서버 기동 `instrumentation` → `startRoadVideoTrackScheduler`
- 주기: **1분** 슬롯. 이미 분석 중이면 그 분의 틱은 건너뜀 (**동시 1건**)
- 큐: `requested_at IS NOT NULL` 인 행을 **요청 시각 오름차순**으로 보며, 파일이 있고 업로드 안정(2분)된 첫 건을 고름
- 파일이 사라진 요청: `failed` + «영상 파일이 없습니다.» 후 `requested_at` 비움
- 끄기: 런타임 `SCHEDULER_CODES.roadVideoTrack`

한 건 처리 절차:

1. 같은 방향 분할 파일 목록 구성  
2. 노선 선형·교차 구역·분기 m/구역·수동점 로드  
3. 임시 JSON 작성 → `python -m pipeline.road_video_track`  
4. 성공 시 분할별 `saveDone`(track + anchor 교체). 분석 중 새로 들어온 요청(`requested_at`이 시작 시각보다 큼)은 유지  
5. 실패 시 해당 파일들 `saveFailed`, 앵커 삭제  
6. 수동점은 이번 분석 입력으로 반영된 뒤 **목록에서 비움**(다음 자동 맞춤에 중복 강제되지 않게). 다시 찍으면 새로 저장  
7. OpenCV/numpy/모듈 없음 → 그 기동 동안 스케줄러 중단(파일을 failed로 도배하지 않음)

| 실행 파라미터 | 값 |
|---------------|-----|
| Python | 파이프라인 공용 bin + `pipelinePythonSpawnEnv` |
| 모듈 | `pipeline.road_video_track` |
| 타임아웃 | 90분 (초과 시 종료·실패 처리) |
| 의존성 | `opencv-python-headless`, `numpy` |

수동 실행: `scripts/run-road-video-track-once.ts`, `scripts/run-road-video-reanalyze.ts`

## 5. 분석 알고리즘 (Python)

핵심 아이디어: **영상에서 “얼마나 돌고 얼마나 갔는지”를 재고**, 대장 노선의 **굽이(방위 변화) 패턴**에 시계열로 붙인다.  
절대 GPS가 없으므로 “어디서 꺾였는지”가 위치를 가늠하는 주 단서이고, 도로면으로 잰 전진 거리는 보조다.

라이브러리·기법: **OpenCV**(ORB 특징점, BFMatcher), **NumPy**, 맞춤은 **DTW 계열 동적 계획**(시간 묶음 ↔ 노선 표본).

### 5.1 입력·출력

입력(스케줄러가 작성):

```json
{
  "video": "단일 경로",
  "videos": ["상행1", "상행2"],
  "route": [[x, y], ...],
  "zones": [[[x,y],...], ...],
  "landmarks": [분기_노선시작기준_m, ...],
  "manualLandmarksByPart": [[{"t": 초, "m": 노선m}, ...], ...],
  "preferDirection": "forward"
}
```

- `route` / `zones`: SRID 5181 미터 좌표. zones = 교차시설 외곽 + 분기 버퍼 원형  
- `landmarks`: 분기점의 노선 시작 기준 거리(m)  
- `manualLandmarksByPart`: 분할 파일별 수동점(로컬 초). 분석기가 이어붙인 전역 시각으로 합침  
- `preferDirection`: 파일명 상행→forward, 하행→reverse. 있으면 **그 방향만** DTW (직선에서 상·하행 뒤집힘 방지)

출력: `ok`, `direction`, `durationSec`, `routeLengthM`, `cost`,  
`anchors`: `[영상초, 노선시작기준_m, 영상속_차정면각]`, `loops`, `partDurations`, `analyzerVersion`

### 5.2 1단계 — 영상 모션 측정 (`measure_motion`)

전제: 지붕 거치 **360° equirectangular**(가로 전방위).

1. 프레임을 **1280×640**으로 축소, 그레이스케일  
2. **0.5초**마다 1장 (fps×0.5 프레임 간격)  
3. **ORB** 특징점(최대 약 4000) + **Brute-Force Hamming** 매칭 (Lowe 비율 0.75)  
4. 마스크: 위쪽 하늘·아래쪽 차량 지붕 제외, **중간 띠(도로·주변)**만 사용  

각 샘플에서 뽑는 양:

| 값 | 의미 | 산출 방식 |
|----|------|-----------|
| **yaw(°)** | 차량 좌우 회전 | 정면·뒤쪽 축 근처 점의 경도(가로) 흐름 중앙값. 카메라가 살짝 틀어져도 “정면”을 흐름 부호가 갈라지는 각으로 재추정 |
| **ds** | 전진량 (카메라 높이 단위) | 수평선 아래 도로면 점의 평면 이동량 중앙값. 노면 무늬·과수원 등에 따라 스케일이 들쭉날쭉 |
| **front(°)** | 영상 속 “차 코” 방향 | 위 FOE(초점) 추정. 저장 전 ~30초 원형 이동평균으로 매끄럽게 |

여러 파일이면 시간축을 이어 붙이고 `partDurations`에 각 길이를 남긴다.  
전진 결측은 보간·짧은 중앙값 필터로 메운다.

### 5.3 2단계 — 전처리 (정차·로터리·묶음)

| 처리 | 내용 |
|------|------|
| 출발 전 정차 | 창 평균 \|yaw\|가 매우 작으면 아직 미출발 → DTW에서 제외, 위치 0에 고정 |
| 도착 후 정차 | 창 평균 전진이 낮아지면 이동 종료 → 이후는 노선 끝에 고정 |
| 로터리(한 바퀴) | 약 25초 창에서 회전합 **> 270°** 이고 회전이 빠른 구간 → `loop` 플래그 |
| 시간 묶음 | 이동 구간을 **2초 블록**(0.5초×4)으로 묶어, 블록별 Σyaw · Σds · loop 여부 |

### 5.4 3단계 — 노선 쪽 준비

1. 노선 좌표를 진행 방향으로 **일정 간격(기본 5m)** 리샘플. 긴 영상이면 메모리 예산에 맞춰 간격을 키움  
2. 각 표본의 **방위각 φ**(전후 ~15m 창)  
3. zones로 **회전 허용 마스크**: 표본이 교차·분기 면 안(±약 15m 패딩)이면 `zone_ok`  
4. 영상 전진량 합을 노선 길이에 맞춰 **스케일** (`bds_m = bds × length / moving`) — 절대 m이 아니라 “상대 진행”으로 맞춤  

### 5.5 4단계 — DTW로 시간↔노선 붙이기 (`_dtw`)

비교 대상:

- 영상 블록 i: 회전량 `byaw[i]`, (스케일된) 전진 `bds_m[i]`, 로터리 여부  
- 노선 표본 j: 방위 `phi[j]`  

상태: “이번 2초 동안 노선을 **a칸**(× step_m 미터) 전진해 표본 j에 도착”.  
비용(개념):

- **방위 일치:** `(sign × 영상회전 − 노선 방위변화)²` — 굽이가 주 단서 (`SIG_YAW` ≈ 5°)  
- **거리 일치:** `(전진거리 − 영상전진)²` — 시그마를 넓게·거리에 비례 키워 **약하게** (`SIG_DIST` ≈ 15m + 0.5×ds)  
- **가감속 벌점:** 직전 블록 전진칸 수와 이번 칸 수 차의 제곱 (`ACCEL_PENALTY`) → 속도가 계단처럼 튀지 않게  
- **로터리 블록:** 방위 비교 대신 “많이 전진하면 벌점”, 그리고 **zone 밖이면 거의 금지**(구역 안에서만 제자리 회전)  
- **zone 안 일반 구간:** 방위 가중치를 낮춤(로터리 S자 통과 등)

`sign` +1/−1: 영상 회전 부호와 노선 좌우가 반대인 경우(카메라·진행 정의)를 커버.  
`direction` forward/reverse: 노선 좌표를 뒤집거나 그대로.  
→ **(방향 × 부호)** 조합 중 **총비용 최소**를 고른다. `preferDirection`이 있으면 방향은 고정하고 부호만 고른다.

역추적으로 블록마다 노선 거리 `s`를 얻고, 블록 안은 전진 비율로 0.5초 보간 → 짧게 이동평균 → **되돌아가지 않게** 누적 최대.

### 5.6 5단계 — 보정 (분기 → 수동)

**분기 자동 보정 (`_align_by_landmarks`)**

1. GIS 분기 m 목록을 진행 방향 거리로 변환  
2. 영상에서 \|yaw\|가 큰 봉우리 시각을 “꺾인 순간”으로 추출(초반 12초 제외, 최소 간격 ~20초)  
3. DTW가 예측한 “그 분기를 지나는 시각”과 실제 큰 회전 시각이 **±약 18초** 안이면 짝을 맺음  
4. 짝지어진 (시각, 목표 m)을 앵커로, 구간마다 기존 s 곡선의 **상대 모양을 유지한 채** 목표 m으로 선형 재매핑  

**수동 기준점 (`_align_by_manual_times`)** — 버전 15

- DTW·분기 보정 **이후**, 알려진 `(t, 노선시작 m)`에서 위치 곡선을 강제 재매핑  
- su가 지도에서 찍은 점 + 영상 시각. 어긋난 자동 맞춤을 국소적으로 바로잡을 때 사용  

### 5.7 6단계 — 앵커 출력

- 전체 타임라인: 정차 앞=0, 이동=보정된 s, 정차 뒤=노선 끝  
- reverse면 저장 시 `route_m = length − s`로 **항상 노선 시작 기준 m**  
- **1초**마다 `[초, route_m, front_deg]`  
- loop 구간은 `loops`로 남겨 화면에 참고  

### 5.8 한 줄 요약

```
ORB로 0.5초마다 회전·전진 측정
  → 정차·로터리 표시 후 2초 묶음
  → 노선 5m 방위와 DTW(굽이 강 / 거리 약 / 가감속·구역 제약)
  → 분기 회전 시각으로 위치 재매핑
  → (있으면) 수동 (시각,m) 강제
  → 1초 앵커 저장
```

현장 감각: 굽이·교차 부근은 대체로 수십 m 안. 대장 선형이 갈래·교량과 한점에 겹치면 오차가 커질 수 있어 수동점이 필요하다. 개발 PC 기준 약 10분 영상당 분석 수 분 수준.

### 6.1 `road_video_track` — 영상 1건 메타

| 컬럼 | 의미 |

| requested_at, requested_by | 스케줄러 대기열 |

### 6.2 `road_video_anchor` — 시각별 위치

| 컬럼 | 의미 |
|------|------|

파일별 `time_sec` + `route_m`. 재분석 **입력**으로 쓰이며, 분석이 **성공하면 스케줄러가 목록을 비운다**(다음에 또 강제되지 않게). UI «수동 기준점»·«다시 분석»은 **계정 `su`만** 표시(요청 API는 슈퍼 `su`·`admin`).

## 7. 화면·지도 연동

### 7.1 진입

`RoadLedgerDetailPanel`이 첨부 목록에서 영상 항목을 모아 `RoadLedgerVideoSync`를 연다.  
영상 창이 열린 동안 지도 속성 클릭 일부는 쉼(노선 근처 클릭은 영상 이동에 사용).

### 7.2 영상 창 (`RoadLedgerVideoViewer`)

- 지도 위 이동·리사이즈·접기 가능 창
- 360° 재생·탐색, 상행/하행 탭(분할은 한 재생 목록으로 이어 재생)
- 재생 시각을 바깥으로 알림 / 바깥 `seekRequest`로 시점 이동
- 상태 줄: 자동 맞춤 완료 · 대기(시간 비율) · 실패(시간 비율) · 지도 따라가기
- `su`: 수동 기준점 · 다시 분석

### 7.3 시각 ↔ 노선 비율 (`roadLedgerVideoTrack.ts`)

- **분석 완료:** 1초 앵커 사이 보간. 같은 지점을 여러 번 지나면 **처음 시각** 사용
- **분석 전/실패:** 영상 시간을 노선 길이에 단순 비율. 파일명 하행이면 끝→시작
- 지도: 비율 → 좌표·진행 방향 / 좌표 → 최근접 비율

### 7.4 지도 레이어 (`useRoadLedgerVideoCarLayer`)

- 노선(옅게) · 지나온 구간(진하게) · 자동차(진행·시야 방향)
- 자동차 드래그·노선 근처(약 12px) 클릭 → 해당 장면으로 seek
- 측정·공간검색·도형 편집 중에는 클릭 연동 무시
- «지도 따라가기»: 차가 뷰포트 안쪽 여백을 벗어나면 지도 이동
- 수동 기준점 모드: 핀 표시·노선 클릭으로 임시점

### 7.5 연동 허브 (`RoadLedgerVideoSync`)

재생 시각 → 자동차 위치, 지도 선택 → 영상 시각.  
분할 재생 시 전역 시각을 파트 로컬로 변환. 대기열이면 주기적 재조회.

## 10. 운영·점검 체크리스트

1. 파이프라인 Python·OpenCV가 서버에 설치되어 있는가.
2. 서버 기동 로그에 도로영상 스케줄러 등록이 보이는가(끄기 설정이 아닌가).
3. `su`로 영상을 열면 `requested_at`이 생기고 1분 내 분석이 시작되는가.
4. 완료 후 상태 «자동 위치 맞춤 완료», 재생 시 차가 노선을 따라가는가.
5. 상행=시작→끝, 하행=끝→시작인가. 분할(상행1→2)이 끊기지 않는가.
6. 로터리·교차 구간에서 차가 한곳에 머물거나 구역을 벗어나지 않는가.
7. 수동 기준점 저장 후 «다시 분석»해도 점이 남고, 위치가 점 근처로 보정되는가.
8. 일반 계정에는 수동점·다시분석이 없고, 기존 결과만 보이는가.
9. 영상 창을 닫으면 노선·자동차 오버레이가 사라지는가.
10. `analyzer_ver`를 올리면 슈퍼가 열 때 재요청되는가.

## 11. 제약·주의

- GPS 부재로 **절대 위치 보장**은 불가. 대장 선형 품질·교차/분기 레이어 유무에 의존.
- 전진 거리 추정은 노면 무늬에 민감 → 굽이·분기·수동점이 주 단서.
- 분석은 CPU 집약·장시간. 동시 실행 없이 한 건씩.
- Admin은 서비스상 슈퍼로 요청 가능하나, **수동 기준점 UI는 `su`만** 노출.
- DB push/migrate로 테이블을 강제 생성하지 않음 — ensure SQL 경로로 생성.
