## 1. 이 문서를 쓰는 이유

외부에서 «HMM 기반 측정(위치 추정) 알고리즘»을 추천받았다는 이야기만 있고,  
**무엇인지 · 우리 도로영상에 넣으면 어디가 좋아지는지**가 비어 있다.  
구현 지시서가 아니라 **개념·현재 방식과의 관계·기대 효과·한계**를 정리한 설명 문서다.

한 줄 요약:

> HMM은 “지금 노선 어디에 있는지”를 **숨은 상태**로 두고, 영상에서 잰 회전·전진을 **관측**으로 보고,  
> 시간에 따라 **가장 그럴듯한 위치 경로**를 확률로 고르는 틀이다.  
> 우리가 쓰는 DTW 맞춤과 **문제 설정이 비슷**하고, 추천의 핵심은 보통 **확률·불확실성·전이 제약을 더 체계적으로 넣는 것**이다.

## 2. HMM이 뭔가 (비유)

**HMM = Hidden Markov Model (은닉 마르코프 모델)**

| 용어 | 쉬운 말 | 도로영상에서의 예 |
|------|---------|-------------------|
| **숨은 상태 (hidden state)** | 직접 안 보이지만 알고 싶은 것 | “지금 노선 시작점에서 몇 m 지점인가” (5m 칸마다 이산 상태) |
| **관측 (observation)** | 매 시각 센서·영상에서 나오는 값 | 0.5~2초마다의 **회전(yaw)**, **전진량**, (있으면) 분기 통과 신호 |
| **전이 확률** | 이전 위치에서 다음 위치로 갈 가능성 | 2초 동안 보통 0~수십 m만 전진, 뒤로 크게 점프는 거의 0 |
| **방출(관측) 확률** | “여기 있다고 가정하면 이 관측이 얼마나 자연스러운가” | 그 지점 노선 **굽이**와 영상 **회전**이 비슷하면 높음 |
| **비터비(Viterbi)** | 처음부터 끝까지 **가장 그럴듯한 상태열** 하나 고르기 | 시각별 노선 m 경로 = 지금의 DTW 경로와 같은 역할의 결과물 |

비유:

- 노선을 5m짜리 칸으로 나눈 **보드게임 말**이 있다.  
- 매 턴마다 “조금 돌았다 / 조금 갔다”는 **힌트 카드**(관측)만 받는다.  
- HMM은 “말이 지금 몇 번 칸에 있을까?”를 **확률 분포**로 들고 가며,  
  규칙(너무 멀리 못 뜀) + 힌트(굽이와 회전이 맞아야 함)로 말을 옮긴다.

GPS가 있을 때의 **맵 매칭(Map Matching)** 논문·상용에서도 HMM·비터비가 자주 나온다.  
우리는 GPS 대신 **영상 모션**을 관측으로 쓰는 형태다.

## 3. 지금 우리 방식(DTW)과의 관계

현재 `road_video_track.py`는 대략 이렇게 한다.

1. OpenCV로 영상에서 회전·전진 시계열 측정  
2. 노선을 5m 표본으로 두고 **방위 변화·거리**와 맞춰 **동적 계획(DTW류)**으로 경로 선택  
3. 교차·분기 구역, 가감속 벌점, 분기·수동점으로 보정  

이 DTW 단계는 수학적으로 **“비용이 최소인 상태열을 고르는 것”**이라,  
HMM의 **비터비(로그 우도 = −비용)** 와 **뼈대가 같다**.

| | 현재 DTW | HMM으로 보면 |
|--|----------|----------------|
| 상태 | 노선 표본 인덱스 j | 동일 (이산 위치) |
| 관측 | 블록별 yaw·전진 | 동일, 다만 **확률 밀도**로 씀 |
| 전이 | “한 블록에 a칸 전진” + 가감속 **벌점** | 전이 **확률** P(j′\|j) |
| 관측 맞춤 | 방위·거리 **제곱오차 / σ²** | 방출 **확률** P(관측\|j) |
| 결과 | 최소 비용 경로 | 최대 확률 경로 (형식만 다름) |
| 추가 산출 | `fit_cost` 하나 | 시각별 **위치 확신도**, 후보 분포 등 |

그래서 “HMM을 쓴다”는 추천은 대개:

- 완전히 다른 마법 알고리즘이라기보다,  
- **같은 맞춤을 확률 모델로 다시 쓰고**,  
- 전이·관측·불확실성을 **명시적으로 설계·튜닝**하자는 쪽에 가깝다.

우리가 이미 넣은 것(가감속 벌점, zone에서 방위 가중 완화, 전진을 약하게)은  
HMM 관점에서는 **전이·방출 설계**에 해당한다.

## 4. 우리쪽에 적용하면 “어디가” 좋은가

추천을 듣는 이유와, **도로대장 도로영상 맥락에서 체감될 수 있는 지점**을 짝지어 둔다.

### 4.1 직선·비슷한 굽이가 반복될 때 헷갈림 완화

**현상:** 긴 직선, 비슷한 S자 연속 구간에서는 회전만으로는 “여기인지 200m 앞인지”가 애매하다.  
DTW는 **하나의 최소비용 경로**만 고르므로, 초반에 살짝 어긋나면 뒤로 누적될 수 있다.

**HMM이 돕는 점:**

- 같은 시각에 **여러 위치 가설**을 확률로 유지했다가, 나중에 뚜렷한 굽이·분기가 나오면 가설이 갈린다.  
- (배치 비터비만 쓰면 DTW와 비슷해지지만) **전방·후방(Forward–Backward)** 또는 파티클과 섞으면 “애매한 구간은 넓게, 확실한 구간은 좁게”를 표현하기 쉽다.

→ **우리 체감:** 읍내 직선·과수원 구간처럼 전진 노이즈가 큰 곳에서, 다음 삼거리·교차에 **다시 붙는** 성질을 형식적으로 넣기 좋음.

### 4.2 “너무 멀리 점프”를 확률로 막기

**현상:** 우리는 이미 최대 속도·칸 수 상한으로 점프를 막는다.

**HMM이 돕는 점:**

- 전이를 “최대 N칸” 하드컷만이 아니라,  
  **가까울수록 높고 멀수록 낮은 분포**(예: 속도 모델 + 분산)로 두면,  
  애매한 관측이 와도 “갑자기 300m 앞”보다 “살살 전진”이 자연스럽게 이긴다.

→ **우리 체감:** 로터리 직후·정차 직후처럼 관측이 깨질 때 경로가 튀는 경우 완화 여지.

### 4.3 여러 관측을 가중치로 합치기 쉬움

**현상:** 지금은 방위 제곱오차 + 거리 제곱오차 + 벌점을 **손으로 섞은 비용**이다.  
분기 보정·수동점은 DTW **이후** 후처리다.

**HMM이 돕는 점:**

- 방출을 곱(또는 로그합)으로 설계:  
  `P(yaw|위치) × P(전진|위치) × P(분기통과|위치) × P(수동점|위치)`  
- 수동·분기 힌트를 “끝난 뒤 강제로 구부리기”가 아니라,  
  **그 시각 관측이 강한 방출**로 들어가 전 구간에 영향을 주게 할 수 있다.

→ **우리 체감:** 수동 기준점·분기 레이어를 **한 모델 안**에서 다루는 설계가 깔끔해짐.  
(지금 후처리 재매핑도 실용적이지만, 구간 사이 왜곡이 남을 수 있음.)

### 4.4 위치마다 “얼마나 믿을지” 숫자

**현상:** 화면은 done / failed / 시간비율 정도이고, `fit_cost`는 전체 한 값이다.

**HMM이 돕는 점:**

- 시각 t에서 상태 분포의 **퍼짐(엔트로피·분산)** → “이 구간은 불확실”  
- 지도 차 색·상태 문구(신뢰 낮음), 수동점 찍기 유도에 쓸 수 있음.

→ **우리 체감:** 운영·검수 UX. 알고리즘 정확도 자체보다 **어디를 사람이 고칠지** 표시에 유리.

### 4.5 나중에 노선이 “한 줄”이 아니라 “도로망 그래프”가 될 때

**현상:** 지금은 **선택한 대장 노선 한 줄**(정·역)에만 붙인다. 충분하다.

**HMM이 빛나는 전통적 영역:**

- GPS 맵 매칭처럼 **교차로에서 어느 링크로 갔는지** 고를 때,  
  상태가 “링크+오프셋”인 **그래프 HMM**이 강하다.

→ **우리 체감(단기):** 이득 적음.  
→ **중장기:** 여러 노선·연결로를 넘나드는 촬영, 망 단위 자동 분류 등으로 확장할 때만 추천 가치가 커짐.

### 4.6 온라인(재생 중) 추정

배치 분석이 아니라, 재생하면서 위치를 갱신하는 **필터**(전방 알고리즘·파티클 필터)도 HMM 계열로 말하기도 한다.

→ **우리 체감:** 지금은 **서버 배치 분석 + 저장된 앵커**라 필수는 아님.  
실시간 라이브 카메라 연동을 할 때 이야기가 달라진다.

## 5. 기대하면 안 되는 것 (한계)

HMM으로 바꿔도 **관측이 나쁘면** 결과는 나쁘다.

| 한계 | 설명 |
|------|------|
| 영상 모션 품질 | yaw·전진은 여전히 ORB 등에서 나옴. 노면 무늬·정차·흔들림 문제는 HMM이 해결하지 않음 |
| DTW와 동일 골격 | 비터비만 쓰면 “이름만 HMM”인 DTW 재구현이 될 수 있음. 이득은 **모델·불확실성·관측 융합**을 제대로 쓸 때 |
| 튜닝 비용 | σ(회전·거리), 전이 속도 분산, 분기 가중을 데이터로 맞춰야 함. 지금 비용 가중 튜닝과 본질적으로 같음 |
| 계산량 | 상태 수(노선 길이/5m) × 시간 묶음. 우리는 이미 DTW 예산 제한이 있음. HMM도 동일 이슈 |
| 은총알 아님 | 대장 선형이 애매한 갈래·교량 겹침은 GIS·수동점이 계속 필요 |

즉, 추천의 실익은 “갑자기 GPS급 정확도”가 아니라  
**애매 구간 안정성 · 힌트 융합 · 신뢰도 표시 · (장래) 망 확장** 쪽이다.

## 6. 우리 파이프라인에 넣는다면 어디를 건드리나

구현을 가정한 **교체 지점**만 표시한다. (현재 미구현)

```
[유지] measure_motion     ← ORB로 yaw·ds·front (관측 생성)
[유지] 노선·zones·landmarks·수동점 수집
[교체 후보] fit_to_route 의 _dtw
            → HMM 전이·방출 정의 + Viterbi (또는 Forward-Backward)
[유지·흡수] 분기·수동 후처리
            → 가능하면 방출항으로 흡수
[유지] 1초 앵커 저장·스케줄러·화면 연동
```

화면·DB·요청 스케줄러는 **그대로** 두고, Python 맞춤 핵심만 갈아끼우는 그림이 자연스럽다.  
`analyzer_ver`를 올리면 기존처럼 슈퍼가 열 때 재분석된다.

### 상태·관측을 우리 용어로 정의하는 예

- **상태 s_t:** 노선 시작 기준 거리 칸 (0, 5, 10, … m), 방향은 파일명 힌트로 고정하거나 상태의 일부  
- **관측 o_t:** `(Δyaw, ds)` 2초 묶음 + (선택) “큰 회전 발생” 플래그  
- **전이:** s에서 s+a로, a는 속도 모델에 맞는 칸 수 (로터리 구간은 a≈0 허용 확률↑, zone 밖 대회전은 ↓)  
- **방출:** 노선 Δφ와 Δyaw의 가우시안, ds와 a·step의 가우시안 (거리 σ를 넓게 = 지금처럼 약하게)

이 정의면 **지금 비용항을 로그 확률로 다시 쓴 것**에 가깝고,  
그 위에 신뢰도·다중 가설·힌트 융합을 얹는 게 “HMM 추천을 우리식으로 수용”하는 현실적 해석이다.

## 7. DTW 유지 vs HMM 도입 — 판단 가이드

| 상황 | 권장 |
|------|------|
| 지금처럼 단일 노선 배치 맞춤, 정확도는 분기·수동으로 보완 중 | **DTW 유지**해도 무방. 관측(모션)·GIS 품질 개선이 ROI가 큼 |
| 직선에서 밀림이 잦고, 비용 가중만으로 한계 | HMM(또는 동일 골격 + 전방·후방 신뢰도) **파일럿** 가치 |
| 수동·분기를 후처리 없이 한 모델에 넣고 싶음 | HMM 방출 설계가 설명·유지보수에 유리 |
| 여러 링크 도로망으로 확장 | HMM/그래프 맵 매칭을 **본격 검토** |
| 실시간 위치 | 필터형(HMM 전방 / 파티클) 검토 |

**실무 제안(문서 수준):**  
“HMM으로 전면 교체”보다,  
1) 현재 DTW 경로에 **시각별 불확실성 근사**를 붙이거나,  
2) `_dtw`를 비터비+명시적 전이분포로 **리팩터 파일럿**한 뒤 동일 노선으로 A/B  
가 추천 의도를 검증하는 낮은 비용 경로다.

## 8. 용어 정리

| 말 | 의미 |
|----|------|
| HMM | 숨은 상태 + 관측의 확률 시계열 모델 |
| 마르코프 | “다음 위치는 (대략) 지금 위치에만 의존” |
| 비터비 | 전체 구간 최적 상태열 (배치 맵 매칭의 표준) |
| 전방·후방 | 각 시각의 상태 확률(신뢰도) 계산 |
| 맵 매칭 | 궤적·관측을 도로 네트워크/선형에 붙이는 작업 전반 |
| DTW | 두 시계열을 늘려 가며 최소비용으로 맞추는 동적 계획 — 우리 현재 맞춤 핵심 |
| 파티클 필터 | 많은 위치 가설(입자)을 관측으로 걸러 내는 방법. HMM과 함께 “확률적 위치 추정”으로 추천되기도 함 |

## 9. 한 페이지 결론

- **HMM이 뭔가:** 노선 위치를 숨은 상태로, 영상 회전·전진을 관측으로 두고 확률적으로 경로를 고르는 틀.  
- **우리와 관계:** 현재 DTW 맞춤과 **같은 문제·비슷한 해**. 추천은 대개 그 틀을 **확률·신뢰도·힌트 융합**으로 키우자는 뜻.  
- **적용 시 좋은 부분:**  
  - 애매한 직선 구간에서의 가설 유지·재부착  
  - 점프·속도의 자연스러운 제약  
  - 분기·수동점을 모델 안으로  
  - 구간별 신뢰도 → 검수 UX
