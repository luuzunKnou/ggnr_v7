# 민원대장 참고자료 속성 정리

`[공간누리 AI 참고자료]` 내 엑셀 파일 9개를 분석한 컬럼(속성) 정리입니다.  
**공통 속성**과 **파일/시트별 속성**으로 구분했습니다.

## 1. 공통 속성 (민원 접수·처리 공통)

아래는 대부분의 민원접수대장/민원대장에서 쓰이는 개념입니다.  
실제 엑셀 컬럼명은 파일마다 다르므로 **의미 기준**으로 통일한 이름입니다.

| 공통 의미 | 의성하수 | 의성상수 | 안동(영문) | 안동(한글·임시) | 비고 |
|-----------|----------|----------|------------|------------------|------|
| **접수 번호** | 일련번호 | 접수번호 | - | 순번 | No |
| **접수일자** | 접수일시(년/월/일) | 접수일자 | comp_create_date | 접수날짜/접수일자 | |
| **접수자** | 접수직원 | 접수직원 | comp_user_name | 접수자성명 | 접수한 직원 |
| **지역(읍면)** | 읍면 | (접수일자 옆) | - | - | 읍면동, 구천면 등 |
| **상세주소** | 상세주소 | - | comp_req_adr | 주소 | |
| **민원인 성명** | 민원인(성명) | 민원인 | comp_req_name | 신고자(성명) | |
| **민원인 연락처** | 전화번호 | 연락처 | comp_req_tel | 연락처 | |
| **민원 내용** | 민원내용 | 민원내용/상세내용 | comp_contents | 신고내용/처리내용/민원종류 | |
| **조치 결과** | 결과 | 조치결과/민원 처리 내역 | comp_rep_contents | 조치사항/처리내용 | |
| **업체(대행)** | 업체 | 대행업체/업체 | agency | 대행업체 | 업체명 |
| **처리담당자** | - | - | comp_rep_mgr | 처리담당자/현장조사 담당자 | |
| **비고** | - | - | - | 비고 | |

- **이미지(마을상수도 민원처리대장)**와 매핑:  
  No → 접수 번호, 접수일자, 접수자, 읍면, 리동, 마을명, 민원인, 연락처, 민원내용, 조치결과, 조치일자, 업체명, 비고  
  → 위 공통 속성에 **조치일자**, **마을명/리동**을 추가하면 동일 체계로 맞출 수 있음.

## 3. DB/API 설계 시 권장 공통 필드 (기본 속성)

이미지 **마을상수도 민원처리대장**과 위 파일들을 모두 아우를 수 있는 **기본(공통) 컬럼** 제안:

| 순서 | 필드명(예시) | 한글명 | 비고 |
|------|----------------|--------|------|
| 1 | no / complaint_no | 접수번호(일련번호) | |
| 2 | received_at | 접수일자 | 날짜(또는 년/월/일 분리) |
| 3 | received_by | 접수자 | 접수직원 성명 |
| 4 | eupmyeon | 읍면 | 행정구역 |
| 5 | ri_dong | 리동 | |
| 6 | village_name | 마을명 | |
| 7 | complainant_name | 민원인(성명) | |
| 8 | complainant_tel | 연락처 | |
| 9 | content | 민원내용 | |
| 10 | action_result | 조치결과 | |
| 11 | action_at | 조치일자 | 없을 수 있음 |
| 12 | company_name | 업체명(대행업체) | |
| 13 | remarks | 비고 | |
| - | **extra** | **(확장 속성)** | **JSONB – 사용자 추가 속성** |

- **의성/안동 등**에서만 쓰는 항목(정산여부, 원인자여부, 민원종류, 자재사용내용, 급수공사 종류, 단수 지역/시간/원인 등)은 **`extra`(JSONB)** 에 넣어 사용자·사업장별로 확장하는 구성을 추천합니다.

## 4. 요약

- **공통**: 접수번호, 접수일자, 접수자, 지역(읍면·리동·마을명), 민원인(성명·연락처), 주소, 민원내용, 조치결과, 조치일자(선택), 업체명, 처리담당자, 비고.
- **파일별 특수**: 정산여부, 공사명, 원인자여부, 작업량, 민원종류, 자재사용내용, 급수공사 종류, 단수(지역/시간/원인), 홍보방법 등 → **공통 스키마에는 넣지 않고 JSON 확장 필드(extra)** 로 관리하는 것이 유연합니다.

이 정리를 **민원관리 기능 설계**의 기본 속성 + `complaint_extra`(JSONB) 설계에 그대로 반영할 수 있습니다.
