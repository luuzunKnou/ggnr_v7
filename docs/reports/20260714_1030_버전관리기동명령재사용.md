## 목적

버전관리 재시작이 `npm run start`나 `npm run dev`로 고정되지 않고, 실제로 서버를 켠 기동 명령을 그대로 다시 쓰도록 한다.

## 요약

기동 시 `dev`/`start`·프로젝트·타입을 재시작 신호 파일의 boot와 환경변수에 남겨 두고, 명령 실행·start/b·감시 스크립트가 그 값을 읽어 재기동한다. **start/b·exit·Node 런처**는 Next만 끄고, `npm run build`는 살아 있는 기동 Node(`run.ts`)가 한다. GeoServer는 적용 직후 기동하고, 재시작 파이프라인 끝·앱 재기동 경로에서의 중복 기동은 하지 않는다. 명령 실행(새 창)만 새 창 스크립트가 빌드를 맡는다.

## 테스트

1. `npm run start -- …`로 켠 뒤 버전관리 start/b 재시작 시 동일 `start` 명령으로 다시 떠야 한다.
2. `npm run dev -- …`로 켠 뒤 start/b·명령 실행 재시작 시 `dev`로 다시 떠야 한다.
3. 기동 기록 파일이 없으면 재시작이 `dev`로 동작해야 한다.
4. Node 런처 재시작은 Node는 유지하고 Next만 다시 띄워야 하며, 처음 켠 `dev`/`start`를 유지해야 한다.
5. Windows 명령 실행 재시작이 새 창에서 동일 프로젝트·타입·스크립트로 감시·기동이 되어야 한다.
6. 서버를 한 번 재기동한 뒤에야 새 기동 기록이 반영되어야 한다.
7. start/b 재시작 시 «'\\' 경로를 찾을 수 없음» 팝업이 뜨지 않아야 한다.
8. start/b·exit 적용 후 콘솔에 기동 런처가 npm run build를 이어 실행하는 로그가 남아야 한다.
9. Node 런처 모드는 Next만 재기동하고 빌드 주체는 동일 Node여야 한다.
10. 명령 실행(새 창)은 새 창에서 빌드·기동이 이어져야 한다.
