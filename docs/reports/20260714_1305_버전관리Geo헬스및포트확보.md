## 목적

GeoServer가 반쯤 뜬 채 실패 CMD만 남은 상태에서 무조건 start bat를 다시 쳐 잠금·재시도가 반복되는 문제를 줄이고, Next 재기동 시 포트 점유로 `EADDRINUSE`가 나는 경우를 완화한다.

## 요약

Geo 기동 전에 웹/헬스 상태를 보고, 이미 정상이면 start를 건너뛴다. 503(starting)이면 바로 강제 재기동하지 않고 ready 대기를 먼저 한다. 정상이 아니면 중지 후 기동하고 ready될 때까지 기다린다. 적용 직후·Node 런처·명령 재시작(PS)·감시 스크립트·서버 부팅 모두 이 경로를 쓴다. Next를 다시 띄우기 전에 포트가 비어 있지 않으면 점유 PID를 강제 종료하되, 자기·부모 프로세스는 건드리지 않는다. 재시작 OFF에서 Geo ensure가 실패하면 한 번 더 시도한다.

## 테스트

1. Geo가 정상일 때 최신 소스 적용 후 Geo start bat가 불필요하게 반복되지 않아야 한다.
2. Geo가 503(기동 중)일 때 곧바로 stop하지 않고 ready 대기가 먼저 이뤄져야 한다.
3. Geo가 꺼짐·대기 실패일 때 ensure가 stop·start 후 ready를 기다리거나, 실패 시 메시지가 남아야 한다.
4. 재시작 OFF에서 Geo ensure 1차 실패 후 한 번 더 시도해야 한다.
5. 명령 실행 재시작(새 창)에서 포트가 남아 있어도 강제 해제 후 앱이 기동해야 한다.
6. 감시 스크립트 재기동에서도 포트 강제 해제·Geo ensure가 동일하게 동작해야 한다.
7. Node 런처 재기동 시 포트 점유 PID를 끊되 자기·부모는 건드리지 않아야 한다.
8. Geo ensure 실패(재시도 플래그 없음) 시 진행 단계에서 Geo 기동이 오류로 보여야 한다.
9. `npm run dev|start` 부팅 시 Geo ensure 후 설정 시도 로그가 나와야 한다.
