## 목적

5000·25000 수치지형도 중줌에서 도엽 한 장만으로도 수~수십 MB가 내려와 멈추던 문제를 없앤다. 전송·파싱량과 최초(콜드) 로딩 시간을 화면 예산에 맞게 줄이고, 25000은 원본 도면 경로를 쓰지 않는다.

## 요약

경량 캐시를 버전으로 분리하고, 25000은 주요 도로만·5000 중줌은 건물 제외로 피처 폭증을 막았다. GeoJSON은 서버에서 상한·간소화한다. 추가로 최초 로딩은 전 프로파일 일괄 추출 대신 파일 스트림으로 필요한 선만 모아 상한 도달 시 읽기를 끊고, 도엽이 끝나는 즉시 지도에 그린다. 벤치·브라우저로 확인. 25000은 주요도로만+파일 앞쪽 샘플이라 도심·확대 시 피처가 거의 없었고, 선 색이 어두워 항공영상 위에서 안 보였다. 도로 전체+격자 샘플+화면 bbox(캐시가 비면 원본 재스캔)·노란 굵은 선으로 바꿨고 v7 캐시를 다시 채웠다.

## 테스트

1. 수치지형도(25000)를 480m 대역에서 켰을 때 1초 안팎으로 도로선이 보이기 시작해야 한다.
2. 25000을 120m까지 확대해도 원본 도면 전체 다운로드로 수십 초 걸리지 않아야 한다.
3. 여러 도엽이 필요할 때 첫 도엽부터 차례로 그려져야 한다.
4. 수치지형도(5000) 중줌에서 건물 덩어리가 한꺼번에 몰려 멈추지 않아야 한다.
5. 5000을 60m 이하로 확대하면 기존처럼 상세 도면이 나와야 한다.
6. 1000 폴더는 이전과 같이 중줌·고줌이 동작해야 한다.
7. 같은 도엽을 다시 열면 캐시로 첫 요청보다 빨라야 한다.
8. 도엽 테두리만 보이는 960m 이상 구간은 그대로여야 한다.
