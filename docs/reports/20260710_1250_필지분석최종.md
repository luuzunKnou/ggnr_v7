# 결과보고서

2026-07-14 | jdong | 필지분석 v7 최종 통판 (plan 기준 · 현재 소스)

## 목적

지도에서 분석 범위를 정한 뒤 선택한 항목(토지·소유·지목·이용계획·건축물대장·기본도·시설 등)을 한 화면 보고서에서 확인하도록 한다.

필지·건축 연계는 **이중화** ※운영(행정망)과 개발·시연(외부망)을 같은 화면으로 쓰기 위해, 상황에 따라 데이터 출처를 나누는 규칙이다. **필지분석 보강**과 **우클릭 필지정보**가 같은 규칙을 쓴다.

## 요약

사이드바에서 «필지분석»을 켜면 먼저 분석 영역을 고른다. 지도에 사각·다각·원으로 그리거나, 읍·면·동·리 행정경계를 고를 수 있다. 영역을 확정한 뒤에야 좌측 패널에서 분석 항목을 고르고 «분석»을 누른다. 결과는 가운데 보고서형 모달(왼쪽 목차·오른쪽 본문)로 본다. 메뉴를 켤 때 설정 시군구가 화면에 크게 잡히고, 그린 도형이 사업 구역을 벗어나면 경고한 뒤 확정을 막아 다시 그리게 한다.

«분석»을 누르면 우리 DB에서 필지 수·면적·소유·지목 통계를 먼저 구해 모달을 바로 연다. 그다음 토지 목록·보강·건축물대장·이용계획 등은 **100건씩** 끊어 이어서 채운다.

서버 토지 보강·이용계획·우클릭 탭은 **행망만** 담당하고, 브이월드 ※공간정보 오픈플랫폼 는 **브라우저 점진 로딩**에서만 이어 붙인다.

### 데이터는 어디서 오나 (이중화)

토지·소유·공시지가 보강은 **행망을 쓰는 경우**와 **행망을 쓰지 않는 경우**가 처음부터 갈린다. 둘을 한 문장에 섞지 않는다.

**A. 행망을 쓰는 경우 (`GGNR_ENV`가 dev가 아님 — demo·prod 등 운영)**

1. 먼저 KRAS ※토지행정망(KRAS) 으로 토지·소유를 가져온다.
2. 이어서 KOREPS ※부동산공시가격 조회망(KOREPS, 조회코드 KOREPS00011) 으로 공시지가를 채운다.
3. 위 단계에서 **못 채운 필지**는 브라우저에서 브이월드 ※공간정보 오픈플랫폼 로 보강한다.

**B. 행망을 쓰지 않는 경우 (`GGNR_ENV=dev`, 로컬 `npm run dev -- … dev`)**

1. KRAS·KOREPS는 **호출하지 않는다.**
2. 보강은 **브이월드만** 사용한다.

**건축물대장**

- 세움터 ※건축행정 적재 DB(`seum`) 표제를 PNU로 먼저 조회한다. (실시간 세움터 웹 API가 아님. 공동이용센터→ESB ZIP→스케줄 적재.)
- 없거나 실패·타임아웃이면: 공공데이터포털 건축물대장 API.
- 대지위치·지번이 비면 PNU로 행정명·번지 폴백. 도로명은 원천(세움·포털)만.

**시설·기본도**

- 시설 통계·목록은 우리 DB·레이어 정의, 지도 그림은 GeoServer ※지도 서버 WMS.

### 프로젝트 runtime 설정 (연계)

행망 **키·IP·포트·시군구코드**는 `*.runtime.env`에 **미리 적어 둔다**.

| 구분 | 내용 |
| -------------------- | ------------------------------- |
| `KRAS_*`·`KOREPS_*`·`SGG_CODE` | 접속정보·키. 사업별 runtime에 보관 |
| 행망 호출 여부 | `GGNR_ENV`가 **dev가 아닐 때만**(demo·prod). `npm run dev -- <project> dev`면 키가 있어도 브이월드만 |
| 실패·누락 시 | 브이월드·공공데이터포털로 이어감 |
| 세움 DB | 세움 적재 DB 우선 → 실패·타임아웃 시 포털 |

**영양 외부 개발 PC**

- `npm run dev -- build_yy dev` → 행망 미호출. 보강은 브이월드.
- runtime에 KRAS·KOREPS 키는 미리 적어 둬도 dev 실행이면 사용하지 않음.

### 묶음·동시·타임아웃 (소스 기본값)

| 구분 | 기본 | 설명 |
|------|------|------|
| 점진 로딩 묶음 | **100필지** | 표·보강을 이 단위로 이어서 채움 (화면 끊기용) |
| 동시 요청 | **8건** | 토지 연계·건축물 조회 공통 |
| 단건 대기 | **토지 8초 / 건축 10초** | 느린 한 건만 끊고 이미 채운 표는 유지 |

**100건:** KRAS·KOREPS에 한 번에 100건을 넣는 값이 아니다. 행망은 **필지 1건 = 요청 1번**이고, 묶음 안에서는 **동시 8건**만 돌린다. 100은 표를 얼마나 자주 이어서 채울지 정한 화면 묶음이다.

묶음·동시·단건 대기는 행망·포털이 느려도 화면이 멈춘 것처럼 보이지 않게 소스에 둔 **운영 기본값**이다.

### 느릴 때·일부만 실패할 때

필지가 많으면 **100필지씩** 나눠 처리한다. 어떤 묶음에서 망이 끊기거나 시간이 초과되면 그 묶음만 비워 두고, 이미 채워진 표·통계는 **유지**한다.

연계가 일부라도 실패하면 모달에 **한 줄**만 띄운다. «연계가 끊기거나 시간 초과로 일부 항목이 비어 있습니다.» «미상»·빈 칸이 그 상태의 표시다.

### 결과 화면

소유자·지목 현황은 구분별 색칠 지도와 통계 표를 같이 보여 주고, 기본도·시설은 지도 캡처로 보여 준다. 테마 지도와 캡처는 휠·드래그·줌 버튼 없이 고정 그림처럼 보이며, 그 설정은 둘이 같이 쓴다. 시설(도로·하천·기타 등) 캡처는 **해당 섹션 표에 나온 레이어만** 그린다(그룹 publish 전체 아님).

테마 지도 색·범례는 토지현황 **보강 값**으로 칠한다(서버는 필지 번호·도형만 주고 색은 화면에서 맞춘다).

**범례·«그 외» 묶음 (소유자·지목 공통)**

분석 필지가 **2,000건 이하**이면 나온 소유구분·지목을 **전부** 각각 색칠·범례에 낸다.  
분석 필지가 **2,000건을 넘으면** 면적이 큰 순으로 **상위 10개 구분**만 지도·범례에 개별 색으로 두고, 나머지는 **«그 외»**로 묶어 한 색으로 칠한다. 통계 표에는 구분 모두 나온다.  
이때 소유자·지목 현황 **제목 아래**에만 «2,000건 초과·그 외» 안내를 작은 글씨로 표시한다(이하일 때는 안내 없음).

**한계·후속:** 위 2,000건·상위 10구분은 측정 근거가 아닌 실무 상한이다. 실제 영역 규모·응답·화면 반응에 따라 **필지 수 상한과 범례(상위 구분) 수 조정이 필요**하다.

## 테스트

1. 사이드바 «필지분석» 선택 시 영역 지정 모달만 열리고 좌측 패널은 없어야 한다.
2. 모달 X·취소(영역 미확정) 시 모드가 종료되어야 한다.
3. 도형·행정경계로 영역 확정 후 좌측 패널·지도 영역 표시가 나타나야 한다.
4. 사업 구역 이탈·일부 이탈 시 경고가 보여야 한다.
5. «분석» 후 결과 모달에 필지 수·면적·소유·지목 통계가 먼저 보여야 한다.
6. 토지현황이 «N / M건»으로 이어 채워지고, 소유·공시지가 보강이 반영되어야 한다.
7. `GGNR_ENV`가 dev가 아니면(demo·prod) 필지분석 토지 보강이 KRAS·KOREPS를 쓰고, 못 채운 필지·이용계획·우클릭은 브이월드로 이어져야 한다.
8. `GGNR_ENV=dev`(로컬 dev 실행)이면 KRAS·KOREPS 없이 브이월드만 써야 한다.
9. 토지이용계획·건축물대장·시설 항목 선택 시 해당 섹션이 채워져야 한다.
10. 소유자·지목 섹션에 색칠 지도·범례·표가 있고, 휠·드래그·줌 버튼이 없어야 한다.
11. 필지 2,000건 이하이면 소유·지목 구분이 범례에 각각 나오고, 2,000건 초과이면 상위 10구분만 개별·나머지는 «그 외»로 묶여야 한다.
12. 테마 지도 색·범례가 토지현황 보강 결과(표)와 맞아야 한다.
13. 기본도·시설 캡처도 고정 표시여야 한다.
14. 연계가 일부 실패해도 표·통계는 유지되고, 모달에 «연계가 끊기거나 시간 초과로 일부 항목이 비어 있습니다» 한 줄만 나와야 한다.
15. 다른 지도 메뉴 전환 시 필지분석 잔여 UI가 없어야 한다.
