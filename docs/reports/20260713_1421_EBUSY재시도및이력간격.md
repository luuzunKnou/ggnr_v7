# 결과보고서

2026-07-13 | 200BingSu | EBUSY 복사 재시도·이력 새로고침 간격

## 목적

파일 잠김(EBUSY 등)으로 복사가 실패할 때 재시도하고 원인을 분명히 알리며, 서버 재기동이 끝난 뒤에도 이력이 갱신되도록 새로고침 간격을 늘린다.

## 요약

복사 시 잠금 오류면 최대 4회 재시도한다. 최종 실패 시 경로·잠금 가능 안내를 포함한 오류를 낸다. 재시작 예약 후 이력 새로고침은 즉시·5·15·30·60초에 시도하고, 화면을 떠나면 타이머를 지운다.

## 파일수정

수정 | src/service/sourceVersionService.ts
 `copyFileWithRetry` — EBUSY·EPERM·EACCES 시 대기 후 재시도. 최종 실패 시 경로·잠금 안내 포함 오류
 `copyRecursive` — 단일 복사 대신 재시도 복사 사용

수정 | src/app/(pages)/dev/_components/devVersionHistoryBridge.ts
 `notifyDevVersionHistoryRefreshRetry` — 기본 간격 즉시·5·15·30·60초. 타이머 id 반환
 `clearDevVersionHistoryRefreshRetry` — 예약된 새로고침 타이머 정리

수정 | src/app/(pages)/dev/_components/VersionManagerContent.tsx
 이력 재시도 — 재시작 예약 시 긴 간격 적용. 언마운트 시 타이머 정리

해당 없음

## 테스트

1. GeoServer 기동 중 적용 시 잠긴 파일이 있어도 재시도 후 복사가 성공하거나, 실패 시 경로·잠금 안내가 나와야 한다.
2. 재시작 예약 적용 성공 후 최대 약 1분 안에 이력 목록이 갱신될 수 있어야 한다.
3. 적용 직후 다른 메뉴로 나가면 이력 새로고침 타이머가 남지 않아야 한다.
4. 재시작 없이 적용 성공 시 이력이 바로 갱신되어야 한다.
