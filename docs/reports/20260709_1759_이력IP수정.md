# 결과보고서

2026-07-09 | 200BingSu | 버전관리 이력 IP 기록

## 목적

버전관리·소스 업로드 이력에 접속 URL(서버 주소)이나 localhost가 아닌, 기능을 실행한 브라우저 사용자 PC의 IPv4를 기록한다.

## 요약

서버가 본 클라이언트 IP를 우선하고, 접속 Host와 같은 body IP는 제외하도록 선택 로직을 수정했다. 브라우저 측은 접속 hostname을 IP로 쓰지 않고 WebRTC로만 PC IPv4를 조회한다.

## 파일수정

수정 | src/lib/requestClientMeta.ts
 `pickClientIp` — 서버 비루프백 IPv4 우선, Host와 동일한 body IP 제외, localhost 시 body(WebRTC) 보조
 `pickClientIpFromRequest` — 요청 헤더·body를 묶어 IP 선택
 `extractIpv4FromHost` — Host 헤더에서 IPv4 추출

수정 | src/lib/clientMachineIp.ts
 `resolveClientMachineIp` — hostname을 IP로 쓰지 않음, WebRTC+STUN으로 사설·공인 IPv4 조회

수정 | src/app/api/dev/version-history/route.ts
 POST — `pickClientIpFromRequest`로 이력 IP 기록

수정 | src/app/api/source/version/install-zip/build/route.ts
 POST — 설치 ZIP 이력 IP에 동일 로직 적용

수정 | src/app/api/source/upload/current/route.ts
 POST — 소스 업로드 이력 IP에 동일 로직 적용

해당 없음

## 테스트

1. 다른 PC에서 `http://서버LAN주소:포트/dev` 접속 후 설치 ZIP 생성 시 이력 IP가 해당 PC 주소(또는 사설 IPv4)여야 한다.
2. `http://192.168.x.x:포트`로 접속해도 이력 IP에 서버 주소만 들어가지 않아야 한다.
3. `localhost` 단독 개발 시 WebRTC로 사설 IPv4가 잡히거나, 없으면 비워 두어야 한다(127.0.0.1·localhost만 저장되지 않음).
4. 최신소스 적용·소스 업로드 성공 후 이력 IP가 동일 규칙으로 기록되어야 한다.
