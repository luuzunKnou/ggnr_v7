# 결과보고서

2026-08-20 | dev.strcat | —
## 목적
영양처럼 서버를 띄울 때 점사용료 테이블이 만들어지는 자리에, 차세대 연계용 스키마와 오류·조회 테이블도 같이 두도록 한다.

## 요약
서버 기동 시 점사용료와 같은 확보 경로에서 차세대 연계 스키마와 오류 로그·조회 테이블이 없으면 만든다. 이미 있으면 그대로 둔다. 저장 데이터는 건드리지 않는다.

## 파일수정
수정 | src/service/ensureLayerAppTables.ts
 `ensureNextGenLinkageTables` — 서버 기동 때 차세대 연계 스키마와 오류 로그·조회 테이블이 없으면 생성. 점사용료와 같은 일괄 확보에 포함
 `ensureNamedSchemaTable` — 레이어 스키마가 아닌 테이블은 없으면 만들기만 하고 옮기지 않음

수정 | src/instrumentation.ts
 기동 안내 — 차세대 연계 테이블도 점사용료와 함께 확보한다고 명시

수정 | src/database/schema/ngl_error_log.ts
 `nglErrorLog` — 기동 시 만드는 오류 로그 테이블 컬럼·기본값과 맞춤

수정 | src/database/schema/ngl_query_table.ts
 `nglQueryTable` — 기동 시 만드는 조회 테이블 컬럼·필수값·기본값과 맞춤

수정 | scripts/ensure-occupation-ledger-tables.ts
 `ensureNextGenLinkageTables` — 수동 확보 스크립트에도 점사용료 다음에 같은 테이블 생성

수정 | src/service/devTestService.ts
 주석 — 개발 점검 시 차세대 연계 테이블도 선확보한다고 명시

## 테이블 수정
추가 | next_gen_linkage.ngl_error_log
 `ngl_error_log` — 차세대 연계 오류 로그. 없으면 서버 기동 시 생성

추가 | next_gen_linkage.ngl_query_table
 `ngl_query_table` — 차세대 연계 조회. 없으면 서버 기동 시 생성

## 테스트

1. 영양 서버를 다시 띄우면 차세대 연계 스키마가 있어야 한다.
2. 오류 로그 테이블과 조회 테이블이 점사용료처럼 없으면 만들어져야 한다.
3. 이미 테이블이 있으면 내용이 지워지거나 덮이면 안 된다.
4. 점사용료·공통점용 테이블 생성은 이전과 같아야 한다.
