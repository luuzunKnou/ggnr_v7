# 결과보고서

2026-10-20 | gyujin | 울산 공공데이터 레이어 그룹명(표준구분) / UAV 레이어 허용목록 제거

## 목적
이미 업로드된 울산 동구 공공데이터 레이어의 그룹명을, 엑셀 표준구분(16대분야) 값으로 맞춘다. UAV 프로젝트에서 데이터조회가 gcp만 보이던 하드코딩 허용목록을 없애고, 시스템별 표시는 프로젝트 구성으로만 제어한다.

## 요약
기존에 공통으로 들어가 있던 «공공데이터» 그룹을 표준구분별로 나눴다. 완료 처리된 52건을 엑셀 파일번호와 테이블명으로 매칭해 반영했다. UAV 전용 테이블 화이트리스트를 제거하고, 울산 런타임에 공간정보 조회·UAV 시스템별 레이어 그룹을 지정했다.

(dev.strcat) 하천 시스템 사이드바에서 «불법점용 관리카드» 프로토타입 메뉴를 숨겼다. 화면 코드와 서비스 목록 항목은 남겨 두어, 하천 시스템 메뉴 목록에 다시 넣으면 바로 보인다. 서비스 목록에서 «사유지분석» 항목이 맨 끝으로 옮겨지며 아이콘 그림 값이 비어 사이드바 아이콘이 사라진 것을, 마지막 커밋의 아이콘 그림으로 되돌렸다(아이콘 파일이 없는 메뉴라 이 값으로만 그려짐). 사유지분석의 분석 구역 레이어가 DB에 없는 사업(영양: 하천구역·소하천구역 없음)은 하천기본계획(소하천은 소하천기본계획) 레이어로 대신 분석하게 했다. 구역 레이어가 있는 사업은 기존 그대로다. 설치 빌드가 Node 메모리 부족(종료 134)으로 멈춘 문제는, 서버 기동 코드가 Python 실행 경로를 리터럴로 써서 빌드 파일 추적이 python/env(수만 개 파일)를 훑던 것을 런타임 결합으로 바꾸고, 빌드 스크립트의 Node 힙 상한을 4GB로 올려 막았다.

## 테스트

1. 레이어 관리에서 그룹이 «공공행정»·«보건의료» 등으로 나뉘어 보여야 한다.
2. «제조업체 현황» 그룹이 «산업고용»이어야 한다.
3. «옥외광고물대장정보» 그룹이 «공공행정»이어야 한다.
4. 기존 한글명·영문 테이블명은 그대로여야 한다.
5. 공간정보 조회 시스템 데이터조회에 표준구분 그룹·공공데이터 레이어가 보여야 한다.
6. UAV 공간정보 조회·관리 시스템 데이터조회에도 표준구분 그룹과 «촬영영상»이 함께 보여야 한다.
7. 개발자 모드 프로젝트 구성에서 시스템별 레이어 그룹을 바꿀 수 있어야 한다.
8. 서버를 다시 띄운 뒤 위 목록이 반영되어야 한다.
9. 하천 시스템 사이드바에 «불법점용 관리카드» 메뉴가 보이지 않아야 한다.
10. 하천 시스템의 다른 메뉴(공사대장·점용대장·보상편입용지 등)는 기존처럼 보이고 열려야 한다.
11. 사이드바 «사유지분석» 메뉴에 아이콘이 다시 보여야 한다.
12. 영양에서 사유지분석을 시작하면 분석 구역 선택에 «하천기본계획»이 나오고, 구간 지정·사유지 목록이 나와야 한다.
13. 영덕처럼 하천구역이 있는 사업에서는 기존처럼 «하천구역»·«소하천구역»만 나와야 한다.
14. 설치 스크립트 빌드 시 «NODE_OPTIONS=… --max-old-space-size=4096» 안내가 찍히고 메모리 부족 없이 빌드가 끝나야 한다.
15. 빌드 후 개발자 모드 LAS 파이프라인 실행과 도로영상 위치 분석이 기존처럼 Python 을 찾아 실행되어야 한다.
