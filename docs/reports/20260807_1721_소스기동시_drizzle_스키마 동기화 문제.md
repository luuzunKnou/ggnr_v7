# 결과보고서

2026-08-10 | 200BingSu | —

## 목적

운영 기동과 최신소스 적용 시 drizzle 스키마 동기화가 데이터 삭제 대화형에 막히지 않도록, 생성만 자동 반영하고 삭제·수정은 고정 정책으로 처리한다. 최신소스 병합 직후에는 변경 집계를 모달로 안내한다. 설치·스모크처럼 키보드 입력이 없는 환경에서도 create/rename 질문에 멈춰 기동이 끊기지 않게 한다.

## 요약

`npm run start` 경로에 고정 정책 additive 동기화를 연결했다. CREATE·ADD COLUMN 등 생성은 항상 적용하고, DROP·DELETE·TRUNCATE는 거부하며, ALTER(타입 변경·컬럼 삭제 등)는 스킵한다. 최신소스 적용 완료 후 dry-run 집계 API와 안내 모달을 추가했고, ALTER 항목은 빨간색으로 표시한다. 체크박스·Y/N 입력·결정 파일은 없다.

추가로, DB에만 있는 테이블(백업·레이어 등)이 «이름 변경 후보»로 섞여 대화형 메뉴에 멈춘 문제를 고쳤다. 코드에 정의된 테이블만 DB와 비교하고, 스키마·테이블명이 다르면 새로 만들기(create)를 자동 선택하며, 같은 스키마에 같은 테이블명일 때만 이름 변경(rename)으로 본다.

## 테스트

1. 운영 기동 시 drizzle 데이터손실 확인 UI 없이 앱까지 진행되어야 한다.
2. 스키마에만 있는 새 테이블·컬럼 추가는 자동 반영되어야 한다.
3. DB에만 있는 옛 테이블은 삭제되지 않아야 한다.
4. 데이터 비우기·행 삭제 후보는 실행되지 않아야 한다.
5. 타입 변경 등 수정 후보는 스킵되고 기동은 계속되어야 한다.
6. 최신소스 적용 완료 후 스키마 안내 모달이 열려야 한다.
7. 모달에 체크박스·Y/N 입력이 없어야 한다.
8. 수정(ALTER) 구역·건수·목록이 빨간색으로 보여야 한다.
9. 모달 확인 전에는 재기동 대기(새로고침)가 시작되지 않아야 한다.
10. 미리보기 실패 시에도 확인 후 고정 정책으로 재기동이 이어져야 한다.
11. 개발 기동은 기존 대화형 스키마 반영이 동작해야 한다.
12. DB에만 있는 테이블이 많아도 create/rename 메뉴에 멈추지 않고 기동이 이어져야 한다.
13. 코드에만 있는 테이블은 이름 변경이 아니라 새로 만들어져야 한다.
14. 설치 기동 검사(스모크)에서 스키마 단계 타임아웃으로 조기 실패하지 않아야 한다.
