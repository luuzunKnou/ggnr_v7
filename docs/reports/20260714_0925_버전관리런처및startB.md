## 목적

최신소스 적용 후 재시작을 «start/b(Node 포함 전체 재기동)»와 «Node 런처(앱만 재기동)»로 나눠, 원하는 방식으로 고를 수 있게 한다. 평소 기동은 `npm run dev -- 프로젝트 타입`을 유지한다.

## 요약

기존 같은 창 재기동은 `start/b` 라디오로 두고, Node까지 다시 띄운다. 새로 추가한 «Node 런처»는 기동 스크립트(Node)를 살려 두고 웹앱(Next) 자식만 종료·재기동한다. 적용 시 신호만 남기며 `process.exit`하지 않는다.

## 파일수정

수정 | scripts/run.ts
 `spawnNext` / `relaunchNextOnly` — Node 부모는 유지하고 Next 자식만 종료·재기동
 `startLauncherPoll` — 재시작 신호가 런처 모드일 때 앱만 재기동·개방망이면 의존성 설치 후 기동

수정 | src/service/sourceVersionService.ts
 `RestartMode` — `startB`·`launcher` 추가 (`nodeWatch`는 API에서 start/b로 호환)
 `scheduleRestart` (startB) — 같은 창 start/b로 Node 포함 재기동
 `scheduleRestart` (launcher) — 종료 없이 신호만. 런처가 앱만 재기동

수정 | src/app/(pages)/dev/_components/VersionManagerContent.tsx
 재시작 라디오 — `start/b`, `Node 런처(앱만 재실행)` 분리

수정 | src/lib/sourceVersionClientRelay.ts
 `RestartMode` — startB·launcher 사전검사

수정 | src/app/api/source/version/update-latest/route.ts

수정 | src/app/api/source/version/relay/init/route.ts

## 테스트

1. `npm run dev -- build_yy dev`로 띄운 뒤 콘솔에 런처 감시 안내가 보여야 한다.
2. «Node 런처(앱만 재실행)»로 적용하면 새 CMD가 뜨지 않아야 한다.
3. 같은 콘솔에서 Node는 유지되고 웹앱만 다시 떠야 한다.
4. «start/b»로 적용하면 같은 창에서 Node 포함 전체 재기동이 되어야 한다.
5. «명령 실행 재시작(새 창)»은 새 창·기존 콘솔 종료가 되어야 한다.
6. 개방망+런처 적용 시 앱 재기동 전에 의존성 설치가 되어야 한다.
