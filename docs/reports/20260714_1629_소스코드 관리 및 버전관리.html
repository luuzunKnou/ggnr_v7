목적

소스코드 관리 및 버전관리 개발자가 <<소스코드 관리>> 내 '설치파일 다운로드'를 통해 설치 파일을 받고 해당 파일을 대상 서버에 설치할 수 있고, '소스코드 업로드'를 통해 현재 코드를 GNMS에 업로드할 수 있다. 업로드 전 '빌드 검사'으로 현재 코드의 npm run build 통과 여부를 임시 복사본에서 검사할 수 있다. 사용자가 <<최신 소스 적용>>에서 적용 버전 및 폐쇄망/개방망 여부와 재시작 방식(프로세스 종료/Node 런처/재시작 안함)을 선택해 '최신 소스 전체 적용'을 통해 자동으로 소스를 최신화할 수 있도록 구현한다. 위 과정은 이력 목록에 남기고 추후 검색, 조회할 수 있도록 구현한다.

Window 서비스 등록 따른 로그 백업 스케줄러 Window 서비스 등록시 로그를 보여주는 cmd 창을 바로 볼 수 없고, Window 서비스의 로그 경로를 설정해야 해당 로그에 대한 실시간 로그를 볼 수 있다. 서비스 등록후 해당 로그에 대한 스케줄러 작업을 통해 날짜별 로그를 확인할 수 있도록 구현한다.

요약

소스코드 관리 및 버전관리 개발자는 «소스코드 관리»에서 설치파일 다운로드(GNMS 최신 또는 현재 서버·폐쇄망/개방망)·현재 코드 업로드로 GNMS에 소스를 올린다. 업로드 전 «빌드 검사»로 임시 복사본에서 빌드 가능 여부를 보며, 같은 화면에서 한 번도 검사를 끝내지 않은 채 자동 업로드하면 확인을 묻는다. 업로드·설치 ZIP·빌드 검사·최신 소스 적용 중에는 예상 소요 시간(약 n분)을 안내한다. 사용자는 «최신 소스 적용»에서 적용 버전·폐쇄망/개방망·재시작 방식을 고른 뒤 전체 적용으로 운영에 반영한다. «최신소스 일부 적용(준비중)»은 비활성이다. 적용 버전은 GNMS 목록을 받아 기본은 최신이고, 과거 버전은 준비 후 받아 중계한다. 적용 시 GeoServer를 중지한 뒤 병합하고, 재시작 여부와 관계없이 병합 후 GeoServer를 다시 기동한다(재기동 시 런처에서 한 번 더 확인). 개방망·재시작이면 사전 패키지 설치·사전 빌드 후 종료한다. 재시작으로 연결이 끊기면 실패가 아니라 안내로 보고, 서버가 안정되고 적용 성공 이력이 반영된 뒤에 화면을 새로고침한다. 적용 중에도 실시간 로그 칸이 보이도록 위쪽(단계)과 아래(로그) 높이를 나눈다. ZIP에 있는 파일만 덮어쓰며 기동용 bat은 패키지에서 빼 둔다. «이력»은 메뉴마다 다르다. «소스코드 관리»는 기능 구분을 고를 수 있고, «최신 소스 적용»은 해당 이력만 본다. 성공 이력의 «버전»에는 날짜·변경 메모만 두고, 본문에는 버전 문구를 넣지 않으며 망·재시작은 «선택»에 둔다. 날짜·기능·성공여부·IP·선택·메모·본문을 통합 검색하고, 검색·초기화로 조회하며 펼쳐 상세를 본다.

Window 서비스 등록 따른 로그 백업 스케줄러 매일 0시에 현재 로그 파일을 'backup' 폴더에 복사한 뒤 '해당날짜_원본이름.log'로 이름을 변경하고 로그파일은 초기화시킨다.

폐쇄망 VM 생성 기존 개방망 VM을 복사한 뒤, DNS 서버 값을 지우고 네트워크 통신 차단한 뒤 내부 네트워크 통신만 허용하도록 설정한다.

테스트

소스코드 관리 > 설치파일 다운로드

  1. «소스코드 관리» «설치파일 다운로드»에서 GNMS 최신 또는 현재 서버를 고를 수 있어야 한다.
  2. 현재 서버일 때 폐쇄망 또는 개방망을 선택하면 ZIP이 받아지고 단계·이력이 남아야 한다.
  3. 진행 중 예상 소요 시간(약 n분)이 보여야 한다.
  4. «이력»에서 설치파일 다운로드 성공·날짜·IP·선택을 조회할 수 있어야 한다.

소스코드 관리 > 소스코드 업로드

  1. «소스코드 업로드» 기본은 설치·node_modules 미포함이어야 하고, «업데이트 (준비 중)»는 비활성이어야 한다.
  2. 이 화면에서 빌드 검사를 한 번도 끝내지 않은 채 «현재 코드 자동 업로드»를 누르면 확인이 나와야 하고, «중단»이면 업로드가 시작되지 않아야 한다.
  3. 빌드 검사를 취소 없이 한 번이라도 끝낸 뒤에는 확인 없이 업로드가 시작되어야 한다.
  4. «현재 코드 자동 업로드» 시 연결 확인 → 스캔 → 압축·전송 → 원격 반영 순으로 단계가 진행되고 예상 시간이 보여야 한다.
  5. 스키마와 DB가 다르면 확인이 뜨고, «중단»하면 업로드가 이어지지 않아야 하며, «계속 진행»하면 업로드가 이어져야 한다.
  6. node_modules 미포함이면 ZIP에서 빠지고 원격 설치 단계가 있어야 하며, 포함이면 설치 단계를 건너뛰어야 한다.
  7. 업로드가 끝나면 GNMS에 최신으로 등록되고 «이력»에 소스코드 업로드 성공이 남아야 한다.
  8. 업로드·설치 ZIP에 기동용 bat이 포함되지 않아야 한다.

소스코드 관리 > 빌드 검사

  1. «소스코드 업로드»에서 «빌드 검사»·«현재 코드 자동 업로드» 클릭 시 실시간 로그가 이전 내용 없이 새로 시작되어야 한다.
  2. «빌드 검사»을 누르면 로그에 demo·production·임시 복사 안내가 보이고 예상 시간이 안내되어야 한다.
  3. 임시 폴더에서 패키지 설치·빌드가 진행되고, 출력이 실시간 로그에 쌓여야 한다.
  4. 빌드 성공·실패 요약이 로그 마지막에 나와야 한다.
  5. 빌드 검사 중 «빌드 검사»·«현재 코드 자동 업로드»가 비활성이어야 하고, 버전 이력에는 기록되지 않아야 한다.
  6. 기동 프로젝트 없이 실행하면 명확한 오류가 나와야 한다.

최신 소스 적용

  1. «최신 소스 적용» 진입 시 적용 버전 목록이 보이고, 기본 선택은 «(최신)»이어야 한다.
  2. «최신소스 일부 적용(준비중)»은 비활성이어야 한다.
  3. 최신 버전·폐쇄망/개방망·재시작 방식을 고른 뒤 «최신 소스 전체 적용»하면 ZIP 중계·운영 반영이 되고 PC에 ZIP이 남지 않아야 한다.
  4. 과거 버전을 고른 뒤 적용하면 준비 후 해당 버전 ZIP으로 반영되어야 한다.
  5. 과거 버전·개방망 적용 시 준비 단계가 로그·안내에 나타나야 한다.
  6. 적용 중에도 단계 목록과 함께 실시간 로그 칸이 보여야 한다.
  7. 병합 후 GeoServer 기동 단계가 보이고, 적용 후 GeoServer Manager에서 연결되어야 한다.
  8. 「재시작 안 함」이면 적용 직후 이력에 성공이 남고, 「프로세스 종료」·「Node 런처」이면 재기동·이력 반영 후 성공 이력이 남아야 한다.
  9. 성공 이력 «버전»에는 날짜·변경 메모만 있고, 본문에는 버전 문구가 없어야 하며 «선택»에만 망·재시작이 있어야 한다.
  10. 「Node 런처」인데 운영에 프로젝트/타입이 없으면 적용이 막히고 안내가 나와야 한다.
  11. 재시작이 있는 적용에서 사전 빌드(개방망이면 사전 설치도)와 앱 종료 단계가 완료로 보여야 한다.
  12. 재시작으로 연결이 끊겨도 빨간 실패가 아니라 안내로 처리되고, «재기동 대기(새로고침하지 마세요)»·«이력 반영 대기» 후 화면이 새로고침되어야 한다.
  13. 적용 중 «취소»하면 사용자 취소 안내가 나오고, GNMS·중계 정리가 되어야 한다.

이력 관리

  1. «이력»에서 «소스코드 관리»는 기능 구분을 고를 수 있고, «최신 소스 적용»은 기능 구분 없이 해당 이력만 보여야 한다.
  2. «이력»에서 통합검색·검색·초기화로 날짜·기능·성공여부·IP·선택·메모·버전·본문을 찾을 수 있어야 한다.
  3. «이력» 접힌 행은 날짜·성공/실패·IP(소스코드 쪽은 기능명 포함)만 보이고, 펼치면 선택·버전·메모·본문이 보여야 한다.
  4. 적용 보류 없이 처음 기동만 한 경우 최신 소스 적용 성공 이력이 새로 생기지 않아야 한다.

GNMS 「소스코드 업로드」·「설치파일 다운로드」 공통 패키징 기준이다. (ggnr_start.bat도 둘 다 제외.)

공통 제외 (폴더·경로)

  2. .vscode/ — VS Code 개인/팀 설정. 운영에 필요 없음
  3. .next/ — 빌드 산출물. 받는 쪽에서 다시 빌드하므로 올리지 않음
  4. .git/ — Git 저장소 메타. 배포 패키지에 불필요
  5. .yarn/ — Yarn 캐시. 용량만 키움
  6. coverage/ — 테스트 커버리지 결과. 운영 불필요
  7. out/ — 내보내기·빌드 산출 폴더. 운영 불필요
  8. build/ — 빌드 산출 폴더. 운영 불필요
  9. .cad-preview-work/ — CAD 미리보기 임시 작업. 운영 불필요
  10. python/env/ — Python 가상환경. 환경마다 다시 구성
  11. geoserver_modules/data_dir/logs/ — GeoServer 로그. 서버별 이력
  12. geoserver_modules/data_dir/gwc/ — GeoServer 타일 캐시. 용량 크고 서버에서 재생성

항상 제외 (파일·패턴)

  1. next-env.d.ts — Next가 로컬에서 다시 만드는 타입 보조 파일
  2. ggnr_start.bat — 운영 서버 서비스 기동용. 프로젝트명·환경·node 경로가 서버마다 달라 업로드·설치 ZIP에 넣으면 덮어쓸 위험이 있어 제외. 현장에서는 00_make_ggnr_starter.bat으로 생성
  3. *.log — 로그 파일. 서버·날짜별로 다름
  4. 경로에 /.cache/ 포함 — 도구 캐시
  5. 경로에 /.tmp/ 포함 — 임시 파일

개방망 패키지일 때 추가 제외

  1. node_modules/ — 받는 쪽에서 npm install 하므로 패키지에 넣지 않음 (폐쇄망은 포함)

모드 요약

  1. 프로세스 종료(nssm) 적용(GeoServer 중지→병합→GeoServer 기동) → 사전 빌드(서버 가동 중) → process.exit(0) → nssm(또는 기동 런처)이 다시 올림 → 부팅 시 성공 이력 → 클라이언트는 서버 안정·이력 반영 후 새로고침.

NSSM 통해 서비스 등록

NSSM으로 현재 프로젝트(ggnr_v7)를 Windows 서비스로 등록한다.

관련 파일(프로젝트 root):

  • 00_make_ggnr_starter.bat — ggnr_start.bat 생성 + (선택) 기동 검사·nssm 등록·로그 창
  • smoke_ggnr_start.ps1 — 기동 검사(포트 3000, 최대 180초). 진행은 [smoke] 로그로 표시. 종료 시 Next·GeoServer(8080) 정리
  • nssm_install_ggnr.bat — 서비스 등록·시작(이미 있으면 삭제 후 재등록 Y/N)
  • open_ggnr_logs.bat — GGNR·GeoServer 로그 실시간 보기(끊기면 재접속)

1. 권장: 00_make_ggnr_starter.bat 한 번에 (관리자 CMD)

관리자 CMD에서 프로젝트 root의 00_make_ggnr_starter.bat을 실행한다.

  1. where node로 node 경로 확인
  2. root에 node_modules가 없으면 고지 후 «npm install 을 실행할까요? (Y/N)» — Y면 설치, N이면 건너뛰고 계속(기동·검사가 실패할 수 있음)
  3. 프로젝트명(GGNR_PROJECT)·환경(GGNR_ENV) 입력
  4. ggnr_start.bat 생성(이미 있으면 덮어쓰기 Y/N — N이면 기존 파일 유지)
  5. «기동 검사 후 nssm 등록·로그 열기를 진행할까요? (Y/N)»
    • N — 생성만 하고 종료. 이후 수동으로 nssm_install_ggnr.bat → open_ggnr_logs.bat
    • Y — 아래 순서로 진행 (관리자 권한 필요)
      1. smoke_ggnr_start.ps1로 ggnr_start.bat 기동 검사
        • 포트 3000이 비어 있어야 함(이미 서비스·dev가 떠 있으면 실패)
        • 약 5초마다 [smoke] 진행 로그 출력
        • 기동 확인 후 테스트용 Next 프로세스 트리 종료, GeoServer는 stop-geoserver.bat·포트 8080 정리까지 수행
        • 실패 시 nssm 등록 중단
      2. nssm_install_ggnr.bat 호출 — 서비스 등록·시작
        • GGNR_V7이 이미 있으면 «삭제 후 재등록할까요? (Y/N)» — N이면 기존 서비스 유지·등록 생략 후 다음 단계로
      3. open_ggnr_logs.bat 호출 — 로그 창 2개

생성되는 ggnr_start.bat 요지:

  • C:\logs · C:\logs\backup 폴더 확보
  • PATH에 node 디렉터리 추가
  • GGNR_PROJECT / GGNR_ENV 설정 후 npm run start -- <프로젝트> <환경>

2. 서비스 등록만 따로 (nssm_install_ggnr.bat)

이미 ggnr_start.bat이 있을 때 관리자 CMD에서 nssm_install_ggnr.bat만 실행해도 된다.

  • 프로젝트 경로 = bat이 있는 root (ggnr_start.bat과 동일 폴더)
  • 앱 = root\ggnr_start.bat
  • 로그 = C:\logs\GGNR_V7_stdout.log / C:\logs\GGNR_V7_stderr.log
  • nssm.exe는 C:\nssm\win64\nssm.exe 우선 (없으면 PATH / C:\nssm\nssm.exe)
  • 기존 GGNR_V7 서비스가 있으면 고지 후 Y일 때만 중지·제거 후 재등록(N이면 기존 유지)
  • 로그 회전: AppRotateFiles=1, AppRotateBytes=10485760(약 10MB), AppRotateOnline=1
    (크기 초과 시 같은 폴더에 .타임스탬프 파일로 rename 후 활성 로그 재생성)
  • 일자별 백업은 운영(npm run start) 기동 시 Node 스케줄러가 매일 0시에 C:\logs\backup\yyyyMMdd_*로 복사 후 원본 truncate

수동 등록 예 (관리자 cmd)

nssm install GGNR_V7 C:\htdocs\ggnr_v7\ggnr_start.bat
nssm set GGNR_V7 AppDirectory C:\htdocs\ggnr_v7
nssm set GGNR_V7 AppExit Default Restart
nssm set GGNR_V7 AppRestartDelay 3000
nssm set GGNR_V7 AppStdout C:\logs\GGNR_V7_stdout.log
nssm set GGNR_V7 AppStderr C:\logs\GGNR_V7_stderr.log
nssm set GGNR_V7 AppStdoutCreationDisposition 4
nssm set GGNR_V7 AppStderrCreationDisposition 4
nssm set GGNR_V7 AppRotateFiles 1
nssm set GGNR_V7 AppRotateBytes 10485760
nssm set GGNR_V7 AppRotateOnline 1
nssm start GGNR_V7

실시간 로그

  1. open_ggnr_logs.bat 실행 — 활성 파일 C:\logs\GGNR_V7_stdout.log를 -Wait로 보며, 회전·truncate로 연결이 끊기면 재접속
  2. 수동 cmd
powershell -Command "[Console]::OutputEncoding = [System.Text.Encoding]::UTF8; Get-Content C:\logs\GGNR_V7_stdout.log -Encoding UTF8 -Wait -Tail 10"

과거 조각은 C:\logs\GGNR_V7_stdout.log.*(NSSM 회전본) 또는 C:\logs\backup\을 직접 연다.

서비스 삭제

nssm remove GGNR_V7
