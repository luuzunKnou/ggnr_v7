## 목적

GNMS 최신 소스 다운로드 시 잘못된 URL(`/api/source/version`이 두 번 붙는 경로)로 요청되던 문제를 수정한다.

## 요약

최신 버전 조회 응답의 `downloadUrl`이 `/api/source/version/download/latest`처럼 사이트 전체 경로로 오는데, 기존 URL 조합 로직이 GNMS 기준 주소 뒤에 그대로 이어 붙여 `.../api/source/version/api/source/version/download/latest`가 만들어졌다. 이미 경로 중복을 막는 조합 함수가 있어 이를 쓰도록 서버·브라우저 양쪽 적용 경로를 통일했다.

## 파일수정

수정 | src/service/sourceVersionService.ts
 `getGnmsClientConfig` — 최신·다운로드 URL 조합을 기존 단순 이어붙이기에서 경로 중복 방지 조합으로 변경
 `applyLatestSourceFromGnms` — latest 응답의 downloadUrl 조합 시 동일 함수 사용

수정 | src/lib/sourceVersionClientRelay.ts
 `runVersionClientRelay` — 브라우저 중계 다운로드 URL 조합을 동일 함수로 변경

재사용 | src/lib/gnmsSourceUrl.ts
 `resolveGnmsApiUrl` — 이미 base 경로와 겹치는 절대·상대 경로를 올바르게 합침

## 테스트

1. GNMS `latest` 응답의 `downloadUrl`이 `/api/source/version/download/latest`일 때 실제 요청 URL이 `http://{GNMS호스트}/api/source/version/download/latest` 한 번만 나와야 한다.
2. `downloadUrl`이 `/download/latest`만 올 때도 동일한 최종 URL이 나와야 한다.
3. dev «버전 관리»에서 «최신 소스 적용» 시 GNMS ZIP 다운로드가 성공해야 한다.
4. 폐쇄망 relay 적용 흐름에서도 다운로드 단계가 실패하지 않아야 한다.
