# 결과보고서

2026-07-13 | 200BingSu | QC 시나리오 대응 · 버전관리 최신 소스 적용

## 목적

버전관리 «최신 소스 적용» QC에서 드러난 오류 구분·재시작 안전·취소 정리·실패 이력 갱신 문제를 코드에 반영한다. 화면은 취소·시간 초과·일반 실패를 나누어 보여 주고, 서버는 재시작 명령 미설정 시 덮어쓰기를 막는다.

## 요약

QC 점검 후 아래를 반영했다.

CORS·네트워크(응답 없음)와 GNMS HTTP API 오류를 로그·화면 문구로 구분한다. 요청 시간 초과는 사용자 취소와 분리해 «시간 초과»로 표시하고 실패 이력을 남긴다. 명령 실행 재시작인데 재시작 명령이 없으면 다운로드·적용 전에 중단한다(서버도 압축 해제 전 동일 검증). 적용 실패 시에도 이력 패널을 새로고침한다. 세션 시작 후 취소·중도 실패 시 운영 서버 relay 임시 폴더를 삭제한다. 전송·병합 크기 불일치는 빨간 오류·실시간 로그·단계 실패로 표시한다. 청크 단위는 2MB이다.

## 테스트

1. 명령 실행 재시작인데 재시작 명령이 없으면 적용이 시작되지 않고 경고가 나와야 한다.
2. 적용 중 «취소» 시 «사용자가 취소했습니다»만 나오고 시간 초과로 표시되면 안 된다.
3. 요청이 너무 오래 걸리면 «시간 초과»로 표시되고 실패 이력이 남아야 한다.
4. GNMS 연결이 CORS·네트워크로 막히면 로그에 CORS/네트워크 안내가 나와야 한다.
5. GNMS가 HTTP 오류를 주면 API 오류(상태코드) 안내가 나와야 한다.
6. 전송·병합 크기 불일치 시 빨간 오류·실시간 로그·단계 실패가 보여야 한다.
7. 적용 실패 후 «이력»을 열면 방금 실패 건이 보여야 한다.
8. 적용 성공·재시작 예약 정상 흐름은 기존과 같아야 한다.
9. 청크 전송 중 «취소» 후 실시간 로그에 relay tmp 정리 안내가 나오고, 서버 임시 폴더가 남아 있지 않아야 한다.
10. 청크·병합 실패 시에도 해당 세션 임시 폴더가 삭제되어야 한다.
11. 폐쇄망·개방망·재시작 안 함 선택 후 전체 적용이 끝까지 동작해야 한다.
