# 결과보고서

2026-10-26 | gyujin | 지적 세부원도 폴더 경로 변경 후 목록이 그대로인 문제 · 데이터 폴더 표준 경로로 이전

## 목적

원도 폴더 경로를 바꿔도 서버를 다시 띄우면 예전 목록이 나와, 새 폴더를 다시 읽게 한다. 새 폴더는 예전 좌표 파일이 없어 목록이 비어 보였으므로, 월드파일로 위치를 읽게 한다. 원도를 데이터 루트 아래 업무자료 폴더로 옮긴 뒤에는 전용 경로 설정을 없애고, 공통 데이터 루트만 쓰게 한다. 목록을 처음 읽을 때는 진행 막대와 장 수를 보여 준다.

## 요약

원도 목록 보관 파일이 원도 폴더 경로와 묶여 있지 않아, 경로만 바꾸고 서버를 다시 띄워도 예전 길안면 목록을 그대로 썼다. 이제 보관 목록에 읽은 폴더 경로를 넣고, 지금 설정된 경로와 다르면 보관본을 버리고 새 폴더를 다시 읽는다. 브라우저에서 세부원도 패널을 한 번 닫았다가 다시 열면(또는 페이지를 새로고침하면) 새 폴더를 읽기 시작한다. 새 폴더는 예전 좌표 파일 없이 원도 이미지와 월드파일만 있어, 목록이 비어 있었다. 월드파일과 이미지 크기로 네 모서리를 계산해 목록에 넣는다. 장 수가 약 3만 8천 장이라 읍면을 고른 뒤에만 목록·도곽을 그린다. 처음 목록은 원도 이미지를 한 장씩 열지 않고, 월드파일을 여러 개 한꺼번에 읽으며 JPEG 크기는 폴더당 한 번만 읽는다. 예전처럼 한 장씩 열면 수 분이 걸린다. 원도는 더 이상 별도 폴더 설정을 쓰지 않고, 데이터 루트 아래 업무자료·세부원도 폴더만 읽는다. 폴더를 처음 읽거나 보관 목록을 열 때는 패널에 단계·장 수·퍼센트를 보여, 멈춘 것처럼 보이지 않게 한다. 영향 받는 기능은 세부원도 목록이다.

## 테스트

1. 개발 서버를 띄운 뒤 세부원도 패널을 열면 예전 길안면 344장이 아니라 새 폴더 기준으로 장 수가 나와야 한다.
2. 읍면 선택 상자에 새 폴더에 있는 읍면이 나와야 한다.
3. 원도 한 장을 켜면 이미지가 나와야 한다.
4. 서버를 다시 띄워도 같은 경로면 목록이 다시 읽히지 않고 바로 나와야 한다.
5. 읍면을 고르기 전에는 «읍면을 선택하세요»가 나오고, 고르면 그 읍면 원도 목록과 도곽이 나와야 한다.
6. 길안면 고란동 원도를 켜면 지적도 위에 겹쳐 보여야 한다.
7. 세부원도 패널을 처음 열면 수 분 기다리지 않고 1분 안에 읍면 목록이 나와야 한다.
8. 목록·지도 라벨이 «고란동 1»처럼 동명과 번호만 나오고 파일명·긴 폴더명은 보이지 않아야 한다.
9. «… 천전동(… 예안면 천전동)_리사이즈(0)» 폴더는 읍면 «예안면», 동 «천전동»으로 나와야 하고 괄호·리사이즈가 보이면 안 된다.
10. 세부원도 패널을 열면 예전 모자이크 폴더가 아니라 데이터 루트 아래 업무자료 세부원도 폴더 기준으로 장 수가 나와야 한다.
11. 개발·시연 설정에 원도 전용 폴더 항목이 없어야 한다.
12. 목록을 처음 폴더에서 읽을 때 패널에 막대와 «좌표 읽는 중 n/전체»가 나와야 한다.
13. 보관 목록만 읽을 때는 «저장된 목록 읽는 중»이 나오고, 끝나면 읍면 선택이 보여야 한다.
14. 이미 메모리에 목록이 있으면 막대 없이 바로 읍면 선택이 나와야 한다.
