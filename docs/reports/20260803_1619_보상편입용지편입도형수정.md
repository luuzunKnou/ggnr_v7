# 결과보고서

2026-08-03 | gyujin | 편입 지번 도형이 당초 필지 크기로 남는 문제

## 목적

보상편입용지 필지에서 편입 지번(예: 1306-8)과 PNU는 맞는데 지도 도형만 당초(1306-1)처럼 크게 남는 오류를 바로잡는다.

## 요약

PNU만 보고 «편입 기준이다»고 판단하면 안 된다. 1306-8 행은 PNU 끝이 0008이었으나 면적은 약 1494㎡로 당초 1306-1에 가깝고, 실제 지적 1306-8은 약 56㎡였다. 저장·동기화 시 편입 지번으로 pnu·geom을 다시 맞추고, 기존 DB는 전량 재조회로 교정했다.

## 파일수정

수정 | src/service/roadRewardService.ts
 `resolveParcelPnuAndGeomByJibun` — 편입 지번 조회 실패 시에만 당초로 pnu·geom을 함께 폴백. 편입 PNU에 당초 도형을 섞지 않음
 `syncParcels` / `saveParcel` — 편입·당초 지번이 있으면 클라이언트 geom을 덮어쓰고 지적에서 다시 조회
 `fillMissingParcelPnuGeom` — `refreshAll`로 이미 geom이 있는 행도 편입 기준으로 재채움

## 테이블 수정

수정 | layer.road_reward_parcel
 `geom` — 편입≠당초 행 포함 전량 재조회. 예: ogc_fid 34(1306-8) 면적 약 1494㎡ → 56.3㎡, 편입 지적과 100% 겹침

## 테스트

1. 당초 1306-1·편입 1306-8인 필지를 지도에서 보면 작은 필지(약 56㎡)여야 한다.
2. 해당 행 PNU 끝이 0008이고, 도형이 1306-1과 겹치지 않아야 한다.
3. 건 저장 후에도 편입 지번 도형이 당초 크기로 되돌아가지 않아야 한다.
4. 당초와 편입이 같은 지번인 행은 기존과 같이 정상 표시되어야 한다.
