# 결과보고서

2026-08-03 | gyujin | 목록 선택 깜빡임·부모 이전 도형

## 목적

보상편입용지 목록을 선택할 때마다 깜빡이는 현상과, 필지 도형을 고친 뒤에도 지도에 부모(편입 범위)가 옛 도형으로 남는 문제를 해결한다.

## 요약

목록이 선택 id에 묶여 매번 전체 재조회·로딩 화면으로 바뀌며 깜빡였고, 그 과정에서 클라이언트에 남은 이전 도형을 서버 값 위에 다시 덮어썼다. 목록은 최초 1회만 불러오고, 부모 도형이 현재 필지 합과 거의 안 겹치면(직접 그린 넓은 범위는 제외) 필지 합으로 교정하도록 했다.

## 파일수정

수정 | src/app/(pages)/map/_mapContents/road/roadReward/RoadRewardListPanel.tsx
 `loadRows` — `selectedId` 의존 제거, 최초 1회만 목록 조회. 선택 시 전체 재조회·로딩 스피너로 깜빡이던 흐름 제거
 `handleSelect` — 상세만 보강. 연속 선택 시 이전 응답으로 덮어쓰지 않도록 순번 가드

수정 | src/service/roadRewardService.ts
 `repairStaleParentGeomVsParcels` — 필지 합이 부모와 거의 안 겹치면 옛 필지 도형으로 남은 부모를 필지 합으로 강제 교체. 필지를 포함하는 직접 그린 편입범위는 유지
 `listRows` / `getDetailByOgcFid` / `fillMissingParcelPnuGeom` — 로드·필지 보강 후 위 교정 호출

## 테이블 수정

수정 | layer.road_reward
 `geom` — 필지와 어긋난 부모(예: 굴구지·1306-8 건의 약 1494㎡ 잔존)를 목록·상세 조회 시 필지 합(약 56㎡)으로 교정

## 테스트

1. 목록에서 다른 건을 연속 선택해도 목록이 «불러오는 중»으로 바뀌며 깜빡이지 않아야 한다.
2. 굴구지(1306-8) 건 선택 시 지도 편입 범위가 작은 필지(약 56㎡)여야 한다.
3. 직접 그린 넓은 편입범위가 있는 건은 필지보다 큰 부모 도형이 유지되어야 한다.
4. 선택 후 상세·필지 건수가 정상 표시되어야 한다.
